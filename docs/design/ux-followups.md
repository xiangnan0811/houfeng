# 体验走查后续事项

v1.19.0 体验走查中，有一部分修复已随 v1.20.0（PR #586）发布。本文记录其余**已确认方向、尚未实施**的事项。
其中的结论均为 2026-10-09 已确认的方案，推进时不需要重新论证。现行合同仍以
[领域合同](../spec/contracts/README.md) 为准：本文只记录要改什么、为什么改、改到哪里，不改变当前行为承诺。

## 维护规则

- 实施某项时，在同一分支同步本文列出的合同、设计和测试；合并后删除该条目，Git 历史保留来龙去脉。
- 全部条目完成后删除本文，并移除 [设计入口](README.md) 中的链接。
- 实施中发现新的约束或方案调整，先更新对应条目再改代码，避免结论只存在于会话或 PR 讨论里。
- 状态取值：`待实施`（方案已定）、`待定`（仍需产品决定，附推荐）、`维持`（结论是不改）。

### F1 移动端运行观测出现空的“说明/操作”行

- 验收：单测覆盖空说明和空操作；390px 浏览器截图中不再出现只有标签的行。

### F2 工作台资产判断卡的大字与标题不对应

- 状态：待实施
- 现象：资产判断卡标题为“资产跟进待核对”，大字却是 VPS 台数（例如 8），读起来像“8 项待核对”。
- 代码：`web/src/pages/dashboard/dashboardModel.ts`，资产判断的 `value` 取 `assetEvidence.vpsCount`，
  `label` 和 `detail` 来自 `assetSignal()` 的分级信号。
- 依据：`dashboard-web.md:45` 只要求判断摘要固定三项、链接与文案一致，没有规定大字取值。
- 方案：大字与当前信号指同一件事：
  - 跟进待核对：取自动续费待核对与跟进事项之和；
  - 决策待核对：取待决定与决定不续费之和；
  - 续费窗口：取 30 天内待续费台数；
  - 没有待办时：显示 VPS 台数，标题写“已登记 VPS”。
- 验收：`dashboardModel` 与 `DashboardPage` 单测覆盖各级信号的大字；e2e fixture 断言不回退。

### F3 订阅开始日期提供“今天”快捷填入

- 状态：待实施
- 现象：新增订阅时，开始日期默认为空。
- 约束：成本趋势按 `started_at` 归入月份（`subscriptions.md:185`）。如果默认填今天，补录老订阅时成本会重新挤进当月，
  所以**不得默认填入**。
- 代码：`web/src/pages/vps-detail/VPSSubscriptionForm.tsx`，与已有的“使用 VPS 到期日”按钮并列。
- 方案：在开始日期旁增加“今天”按钮（按本地日期），由用户主动点击；字段默认仍为空。
- 同步：`subscriptions-web.md` 中 VPS 订阅表单的描述。
- 验收：单测覆盖点击填入与默认为空。

### F4 补测：存量非法地址直接清空的记史路径

- 状态：待实施
- 来源：PR #586 双审中两方都提出的非阻断建议。
- 代码：`internal/center/store/ip_quality_identity_postgres_integration_test.go` 的
  `assertIPQualityAddressIdentityVPSPatchHistory`。
- 方案：用 SQL 写入存量非法 IPv6 后，直接 PATCH 为空串，断言允许保存且地址身份历史正确记一条。
- 验收：`scripts/test-business-postgres.sh` 通过。

## 第二步：已定方案、需先改合同

- 同步：`subscriptions.md` 幂等与 VPS 范围创建场景、`subscriptions-web.md`。
- 验收：Go 单测、契约正反用例、Postgres 集成测试（同名重放 200，换名 409）、前端单测、e2e。

### C4 入口探测：显式给监控实例加标签

- 状态：待实施
- 现象：首台监控实例没有标签，新用户创建探测目标时没有可选的执行标签。
- 已有：创建目标时的执行者预览与引导（`targets-web.md:28`）。
- 约束：**不做静默的自动默认标签**。执行实例按标签交集匹配，统一默认标签会让所有写了它的目标从全部 VPS 发起探测，
  扩大出站流量和探测来源。
- 方案：
  - 执行标签预览中把现有实例的标签列为可点击选项，点击即填入；
  - 实例都没有标签时，提供“给实例 X 加上标签 Y”按钮，调用现有的监控实例标签修改接口，用户确认后才写入；
  - 可选：接入抽屉完成后建议一个标签。
- 代码：`web/src/pages/targets/CreateTargetPanel.tsx`（`ExecutorPreview`）。
- 同步：`targets-web.md:28`，以及所用实例标签接口所在的合同。
- 验收：单测覆盖选项填入、加标签确认与失败；e2e 覆盖“无标签 → 加标签 → 预览出现执行者”。

## 第三步：单独立项

### P1 术语对照与文案改版

- 状态：待实施（先交付对照表，确认后改）
- 现象：
  - 资产决策页满屏内部术语（“取消与迁移联动核对”“闭环异常”“证据状态 已聚合”“组合证据不足”）；
  - P1 卡片标题与副标题重复；
  - 底部条“保存记录 0 条 / 模板 7 个 / 组合 0 组”难以理解；
  - 顶栏常驻“当前运行异常计数为 0”，多处写“未来 90 天（UTC）”。
- 依据：`asset-decisions-web.md:46-48` 规定表达层级与用语方向；`dashboard-web.md:41` 规定“当前运行异常计数为 0”的使用条件，
  第 49 行规定“未来 90 天（UTC）· N 项”，第 147 行要求顶栏给出状态和服务端生成时间。单测与 e2e 断言的都是这些原文。
- 方案：
  1. 先产出术语对照表（内部概念 → 用户用语 → 涉及的合同与测试），确认后在一个 PR 内同时改合同、实现与测试；
  2. 方向示例：
     - “未来 90 天（UTC）”改为“未来 90 天”，悬停说明“按 UTC 日计算”；
     - 顶栏可见文字改为“运行正常 · 摘要 HH:MM”，完整句子保留在 `aria-label`；
     - 资产决策页底部条拆成带动词的入口。
- 约束：不得削弱 `asset-decisions-web.md:40` 的降级语义；读取失败不得被写成“无问题”。

### P2 历史汇率回补

- 状态：待定（先核实提供方能力）
- 现状：补录的外币历史月份如果当时没有汇率，按此后最早的汇率估算，并标注 `rate_estimated`（`subscriptions.md:185`）。
  缓存在同一 `rate_date` 刷新时会覆盖 `fetched_at`，无法区分“当时没有汇率”和“后来才取到”。
- 结论：不为此新增 `first_fetched_at`，因为补录月份本来就不会有当时的缓存，加字段解决不了问题。
- 方向：如需精确，按日期回补历史汇率。默认提供方 Frankfurter（`internal/center/settings/types.go:172`）的公开 API
  支持按日期查询；Fixer 的历史端点受套餐限制。实施前需核实，并评估回补的触发时机、限流和失败降级。
