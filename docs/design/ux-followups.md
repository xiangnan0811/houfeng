### P1 术语对照与文案改版

- 状态：待实施（对照表已于 2026-10-10 确认，见下表）
- 现象：
  - 资产决策页满屏内部术语（“取消与迁移联动核对”“闭环异常”“证据状态 已聚合”“组合证据不足”）；
  - P1 卡片标题与副标题重复；
  - 底部条“保存记录 0 条 / 模板 7 个 / 组合 0 组”难以理解；
  - 顶栏常驻“当前运行异常计数为 0”，多处写“未来 90 天（UTC）”。
- 依据：`asset-decisions-web.md:46-48` 规定表达层级与用语方向；`dashboard-web.md:41` 规定“当前运行异常计数为 0”的使用条件，
  第 49 行规定“未来 90 天（UTC）· N 项”；第 142 行规定顶栏零计数文案为“当前运行异常计数为 0”，并**禁止**“系统正常”
  “系统摘要无异常”“同步完成”或等价的全链路健康说法；第 147 行要求顶栏给出状态和服务端生成时间。单测与 e2e 断言的都是这些原文。
- 方案：
  1. 先产出术语对照表（内部概念 → 用户用语 → 涉及的合同与测试），确认后在一个 PR 内同时改合同、实现与测试；
  2. 方向示例：
     - “未来 90 天（UTC）”改为“未来 90 天”，悬停说明“按 UTC 日计算”；
     - 顶栏可见文字缩短为与非零形式“运行异常 N”同构的“运行异常 0 · 摘要 HH:MM”，完整句子保留在 `aria-label`；
       不得改成“运行正常”之类的健康结论；
     - 资产决策页底部条拆成带动词的入口。
- 约束：不得削弱 `asset-decisions-web.md:40` 的降级语义，也不得违反 `dashboard-web.md:142` 的健康文案禁令；
  读取失败不得被写成“无问题”。

### P2 历史汇率回补

- 状态：待实施（2026-10-10 确认）
- 现状：补录的外币历史月份如果当时没有汇率，按此后最早的汇率估算，并标注 `rate_estimated`（`subscriptions.md:185`）。
  缓存在同一 `rate_date` 刷新时会覆盖 `fetched_at`，无法区分“当时没有汇率”和“后来才取到”。
- 结论：不为此新增 `first_fetched_at`，因为补录月份本来就不会有当时的缓存，加字段解决不了问题。
- 方向：如需精确，按日期回补历史汇率。默认提供方 Frankfurter（`internal/center/settings/types.go:172`）的公开 API
  支持按日期查询；Fixer 的历史端点受套餐限制。
- 核实（2026-10-10）：现用端点 `https://api.frankfurter.dev/v2/rate/{quote}/{base}`（`internal/center/subscriptioncosts/providers.go`）
  接受可选 `date` 参数，免密钥、无配额但有防滥用限流。
- 已确认方案：后台任务为“补录月份缺少月末前汇率”的币对按月末日期回补历史汇率并写入缓存，每次运行限制回补月数；
  只对 Frankfurter 回补，Fixer 维持现状；回补失败时趋势沿用现有的“按此后最早汇率估算”标注。
