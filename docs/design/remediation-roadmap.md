# 审计整改路线

本页是现行未完成范围的入口；行为和验收以链接的合同为准，旧审计编号只用于追溯。旧审计方案和数字不覆盖现行合同，历史材料按需取证，不是运行依赖。

## G2：持久删除与恢复

依照 [G2 剩余执行路线](g2-plan.md) 推进；其中记录当前状态、依赖和接受条件。

## G1/H4：完整备份与恢复

备份与恢复需要真实编排和 CLI 成功路径，而不只是现有接口或单一数据副本。按[记录集成、备份与恢复合同](../spec/contracts/records/integration-recovery.md)、[当前 APP ACL](../spec/contracts/platform/app-acl-current.md)和 [Compose authority](../spec/contracts/platform/compose-authority.md) 核对恢复单元及授权边界。

下一步补齐真实备份/校验/恢复及失败后的可恢复性：运行中继续读取，只短暂冻结写入；所选内容及其依赖齐备并验证后才恢复服务。工具须加密，恢复密钥独立保管；验证数据库、附件、Records authority 和相关凭据/队列的协调恢复，不能以子集代替完整恢复点。实际验证支持的 local/S3 路径及不可用依赖的明确拒绝。运维异地保存不要求工具新增远端上传、调度或自动删除；备份周期未定不阻塞首次恢复验收。

既定目标要求支持旧版本数据恢复到新版本，高版本到低版本为 best-effort，不能以一律拒绝混版本恢复宣称完成；当前合同只支持同版本、明确不支持混版本恢复，两者仍有缺口。H4 的旧业务数据不能由 0067 自动转换，须明确来源/目标与无损映射、实现兼容转换并实测，不能修改冻结迁移绕过限制；先同步合同再宣称支持。G2 的 K 是 source 物理重新准入的一部分，不覆盖全部备份能力。

## W10：Records 归档与恢复入口

归档/恢复 API 已有，Records 页面仍需接入动作。可独立于 G2 回收站推进：按 capability 和权限显示入口，处理确认、权限变化、重入与权威状态刷新，并以浏览器验证。遵循 [Records Web 合同](../spec/contracts/records/web-surfaces.md)及其引用的记录合同；资产 `/archive` 的语义不变。
