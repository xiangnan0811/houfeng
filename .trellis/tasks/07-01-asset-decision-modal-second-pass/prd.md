# Second-pass asset decision modal declutter

## Goal

资产组合决策页上一轮重构后仍没有达到用户要求。用户反馈：打开某一个组时，弹窗默认内容仍包含大量文字，视觉混乱，无法专注思考；截图只是“预算压力与弱承载”的一个例子，不代表问题只存在于该组或该标题。必须重新做一次以当前发布状态为准的全面审查和返工，解决所有资产决策默认弹窗/页面 surface 的信息密度、文案层级和视觉焦点问题。

## Requirements

- 重新审计当前 `/asset-decisions` 发布状态，不依赖上一轮结论。
- 审计范围必须覆盖：
  - 自动组详情：取消/退役、续费、区域主备、服务商组合、预算压力、证据缺口等代表性组；
  - 自定义组合详情；
  - 保存记录详情；
  - 场景模板详情；
  - 页面主体、续费事实、单台辅助队列、来源复核入口。
- 审计必须区分“默认首屏必须出现的信息”和“可进入二级面板的信息”，不能只统计旧英文标题是否消失。
- 默认弹窗必须进一步收敛为真正的决策卡，而不是压缩版报告：
  - 默认只保留最少字段：标题、状态、极少关键事实、单句判断、最多 1-2 个风险、主动作；
  - 成员/对象默认只允许极短摘要或完全收起；
  - 宽表、成员列表、证据评分、执行编排、来源回读、说明性长句、字段解释、二级导航说明默认不可见。
- 保留所有二级能力，不删除真实工作流：创建/编辑自定义组合、保存记录、成员维护、来源复核、状态跟进、模板创建/归档、单台处理。
- 桌面与移动端都不能出现 document/body 横向溢出；移动端默认弹窗不能像长报告。
- 不改后端 API、数据库 schema 或新增依赖，除非审计证明前端内聚方案无法满足。

## Acceptance Criteria

- [ ] 新审计记录覆盖所有代表性自动组和其他详情入口，并指出每个默认层仍然混乱的具体来源。
- [ ] PRD/design/implement 明确新的默认信息预算，且预算比上一轮更严格。
- [ ] 自动组详情默认打开时，首屏不出现长段 `primary_issue_summary`、`next_step`、完整成员摘要、完整事实解释或多按钮/多导航噪音。
- [ ] 预算压力组不是唯一修复对象；其他自动组和非自动组详情默认层同样达标。
- [ ] 默认层可见文本、badge、按钮、区块数量有可复核的浏览器指标，并较当前 release 明显下降。
- [ ] 二级面板仍可访问原能力并有测试覆盖。
- [ ] 测试覆盖默认信息预算和代表性入口，而不是只断言旧 marker 不存在。
- [ ] 浏览器验证覆盖桌面 `1440x1000`、移动 `390x900`、多组/多入口，无 document/body 横向溢出。
- [ ] 本地质量门通过：`git diff --check`、目标测试、`npm run lint`、全量测试、`npm run build`。
