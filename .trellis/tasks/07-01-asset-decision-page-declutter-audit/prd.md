# Deep declutter asset decision page

## Goal

资产组合决策页需要重新做一次以真实视觉体验为准的全面审查和返工。上一轮只把弹窗内容拆到二级面板，但默认组详情仍然包含大量说明性、重复性、低优先级文字，用户打开任意组后仍然无法快速聚焦判断、风险和下一步行动。

本任务必须解决根因：页面和弹窗的信息密度、文案策略、视觉层级和披露边界不成立，而不是只删除某个截图里出现的标题或只处理“预算压力与弱承载”这一组。

## User Problem

- 打开某一个组时，弹窗首屏仍有太多文字，视觉上混乱。
- 截图只是预算压力中的一个例子，不能把问题限定为该组或该标题。
- 其他组、其他弹窗、甚至页面主体都可能存在同类问题，需要全面分析。
- 用户希望页面条理清晰、主次分明、重点明确、视觉上精致可信。

## Requirements

- 全面审查 `/asset-decisions` 的页面主体和所有详情入口：
  - 自动组卡片 / 表格 / 组详情弹窗；
  - 自定义组合列表与详情；
  - 保存记录列表与详情；
  - 场景模板列表与详情；
  - 续费事实、单台辅助队列，以及从记录复核来源打开的组详情。
- 默认视图必须以决策工作为中心，而不是解释文档：
  - 首屏只保留组名、关键事实、风险等级、主建议、最重要的行动；
  - 弱承载、预算压力、缺证据、退役风险等真实风险不能被隐藏；
  - 但风险表达必须短、强、可扫描，不能堆长句。
- 说明性长文、重复字段、宽表、表单、执行细节、成员长列表必须默认降级或收纳。
- 需要定义跨所有资产决策 surface 的统一文案预算和信息层级，而不是每个区域各写一套说明。
- 移动端和桌面端都必须无 document/body 横向溢出，且首屏内容不能像长文档。
- 不改后端 API、数据库 schema 或新增依赖，除非审查证明没有前端内聚方案。

## Evidence From Current Audit

- 主页面桌面首屏可见文本约 `1136` 字符，badge 约 `63` 个，按钮/链接约 `18` 个；这说明问题不局限于弹窗。
- 自动组详情默认视图仍显示 `5-7` 个区块、`15-24` 个 badge、`9-13` 个按钮；不同组都存在同类密度问题。
- 移动端组详情首屏在到达成员内容前，已经显示摘要卡、决策区、评分条、风险标签和主按钮。
- 保存记录和自定义组合详情仍偏报告化；模板详情相对简洁，可作为收敛方向。
- 详细记录见 `research/visual-audit.md`。

## Product Contract

默认视图必须遵守可见信息预算：

- 页面主体首屏只服务一个目标：告诉用户“当前最需要处理什么”。
- 自动组列表每行只显示：
  - 优先级；
  - 组名；
  - 最多 2 个风险/状态标签；
  - 最多 3 个关键数字；
  - 一个主动作。
- 详情弹窗默认首屏只显示：
  - 标题和最多 3 个状态 chips；
  - 4 个关键事实；
  - 一句主判断；
  - 最多 2 个风险标签；
  - 主要动作；
  - 最多 2 条成员短行。
- 默认视图不显示：
  - score bars；
  - 英文 eyebrow；
  - “支撑/风险/缺口”解释句；
  - panel nav summary 文案；
  - 完整成员长卡；
  - 原始宽表；
  - 表单。

## Acceptance Criteria

- [ ] 真实浏览器审查覆盖多个自动组类型，而不仅是截图中的预算压力组。
- [ ] 真实浏览器审查覆盖自定义组合、保存记录、模板、续费事实、单台队列的默认展示。
- [ ] PRD/design 明确列出页面主体和详情弹窗中的噪音来源、保留内容和降级内容。
- [ ] 自动组详情默认打开时，首屏不出现大段说明文案；关键判断能在一次扫视中完成。
- [ ] 所有详情弹窗的默认视图都有一致的信息骨架和文案预算。
- [ ] 自动组列表默认行不再显示 `NEXT STEP` / `COMPARISON` 双报告块、评分条或完整证据说明。
- [ ] 自动组详情默认不显示 `GROUP DECISION`、`MEMBERS`、score bars、`支撑 N · 风险 N · 缺口 N`、panel summary 小字。
- [ ] 保存记录和自定义组合详情默认不显示 score bars 或多卡 checklist；保留真实状态、目标、风险和主动作。
- [ ] 二级能力仍可访问，不丢失保存、编辑、成员维护、执行跟进、来源复核、模板创建、VPS 处理等能力。
- [ ] 测试覆盖“默认视图文案预算/噪音收纳”和“二级能力仍可用”，不能只断言旧标题不存在。
- [ ] 浏览器验证覆盖桌面与移动端，多组、多入口，无 document/body 横向溢出。
- [ ] 本地质量门通过：`git diff --check`、资产决策页目标测试、`npm run lint`、全量测试、`npm run build`。

## Out of Scope

- 不重写资产决策业务规则。
- 不更改资产决策 API payload 或数据库结构。
- 不把低频能力删除；只能重新组织默认可见层级。
