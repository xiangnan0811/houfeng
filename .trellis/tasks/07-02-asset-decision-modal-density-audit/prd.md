# Fix asset decision modal density audit

## Goal

继续处理 `/asset-decisions` 资产组合决策页面的详情弹窗密度问题，确保用户打开任意自动组、自定义组合、场景模板、保存记录或来源复核时，看到的是清晰的决策工作台，而不是长篇报告、证据矩阵、成员大卡、表单和底稿混在一起的滚动弹窗。

本任务承接用户反馈：“打开某一个组，弹窗显示的内容依旧包含非常多的文字，混乱不堪；截图只是预算压力与弱承载，不代表其他组没有问题，也不只这些组的弹窗有问题。”截图证据为 `/home/murray/.codex/attachments/17ffe930-1848-4cf8-ab30-2f74f10adef4/image-1.png`。

当前代码已经做过默认封面和部分二级面板瘦身，但这不能视为完成：测试主要反向搜索旧 marker 和少量模拟文本，不能证明真实浏览器中的所有典型弹窗已经具备低密度、单任务、可扫描的体验。

## Confirmed Facts

- 当前分支：`fix/asset-decision-modal-density-audit`，非 `main`。
- 任务目录：`.trellis/tasks/07-02-asset-decision-modal-density-audit`。
- 历史归档 `07-01-asset-decision-modal-density-audit` 已经识别根因：默认封面/目录不够，目录后的 `members`、`save`、`execution`、`create` 等正式面板仍可能过载。
- 当前实现中旧截图的 `GROUP TO SCENARIO` / `EVIDENCE MATRIX` 等 marker 已不在源码中，但这只证明一类旧结构被删，不证明当前结构已经符合体验目标。
- 当前 `AssetDecisionsPage.test.tsx` 会通过 23 个测试，但这些测试没有全局量化每个弹窗/面板的文本密度、首屏块数量、按钮数量、成员行复杂度和运行态视觉承载。
- 资产决策详情路径包括自动组、自定义组合、场景模板、保存记录、保存记录来源复核、组内单台 VPS 处理弹窗；不能只修“预算压力与弱承载”一个组。

## Requirements

1. 全面审查当前 `/asset-decisions` 详情弹窗的前端代码、测试、样式和运行态表现，覆盖：
   - 自动组：默认封面、目录、成员、保存记录、底稿、组内单台处理。
   - 自定义组合：默认封面、目录、成员、编辑、添加、保存记录、底稿、移除确认。
   - 场景模板：默认封面、目录、创建组合、成员蓝图、状态维护。
   - 保存记录：默认封面、目录、执行跟进、成员跟进、来源复核、底稿。
   - 来源复核重新打开自动组/自定义组合后的层级。
2. 不能以“旧 marker 不存在”作为完成标准；必须建立正向密度约束：
   - 默认层和目录层只做入口，不显示成员列表、底稿、保存表单、执行编排或长说明。
   - 任一二级任务面板只做一个任务，首屏不混放其他任务的表格、表单或解释段落。
   - 成员面板必须是可扫描的紧凑决策行，不再像成员报告卡；成员事实、provider/product/cost/facts 串和宽表留到底稿。
   - 保存面板必须先显示基础字段和成员复核摘要，成员理由编辑按单成员展开，不一次铺开所有成员表单。
   - 执行面板必须是推进工作台，不把来源回读、成员底稿和完整事实报告混在同一首屏。
3. 针对“预算压力与弱承载”类成本/预算自动组建立专门回归覆盖，同时至少覆盖一个非成本自动组，确保问题不是按单个 group title 修。
4. 保留所有既有写入能力和 payload contract：
   - 创建自定义组合。
   - 保存自动组/自定义组合为决策记录。
   - 编辑自定义组合。
   - 添加/移除自定义组合成员。
   - 另存模板。
   - 从模板创建组合。
   - 更新模板状态。
   - 更新保存记录状态和成员跟进。
   - 组内单台 VPS 决策处理。
5. 不改变后端 API、数据库 schema、路由 contract，不新增前端依赖。
6. 视觉保持当前候风暗色优先、高密度工程工具风格，使用现有 CSS tokens、BEM 和 atoms。

## Acceptance Criteria

- [ ] 运行态审查记录覆盖自动成本/预算组、非成本自动组、自定义组合、场景模板、保存记录和来源复核；每类都有当前问题或合格证据。
- [ ] 打开任一自动组默认弹窗时，不出现成员姓名、成员摘要、保存表单、执行编排、底稿表格或多段长文。
- [ ] 点击自动组 `详情` 后先进入目录，目录不出现成员姓名、底稿字段、内部 ID、来源机器值、表单字段或完整说明句。
- [ ] 自动组 `成员` 面板首屏只展示紧凑成员取舍，不出现证据矩阵、成员报告大卡、底稿表格、provider/product/cost/facts 串，且有文本/区块密度断言。
- [ ] 自动组 `保存记录` 面板不一次性展开所有成员的 `角色` / `动作` / `理由` 编辑控件；保存 payload 与既有测试一致。
- [ ] 自定义组合 `members/edit/add/save/raw` 各自独立，不同任务的表单、底稿、成员报告不会同屏混放。
- [ ] 场景模板 `create/members/status` 去掉普通态长解释；确认文案只在用户触发危险/状态变更确认后出现。
- [ ] 保存记录 `execution/source/members/raw` 保持单任务结构；`查看详情` 不直接进入执行编排；来源复核打开的组同样符合自动组/自定义组合规则。
- [ ] 桌面 `1440x1000` 和移动 `390x900` 打开典型弹窗后 document/body 无横向溢出；表格只允许自身内部横向滚动。
- [ ] `AssetDecisionsPage.test.tsx` 添加失败再通过的回归测试，覆盖正向密度约束、跨类型弹窗和写入 payload 不变。
- [ ] `cd web && npm run test -- --run AssetDecisionsPage.test.tsx`、`cd web && npm run lint`、`cd web && npm run test -- --run`、`cd web && npm run build` 通过。
- [ ] 如产生可复用 UI 规则，更新 `.trellis/spec/web/component-conventions.md`。
