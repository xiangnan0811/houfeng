# Third-pass asset decision workbench IA audit

## Goal

资产组合决策页需要从“压缩报告 / 答辩 PPT”式的信息堆叠，收敛成可扫描、主次明确的决策工作台。第三轮重点不是继续压缩文字数量，而是修正默认信息架构：用户打开任意组合、记录或模板时，第一眼只看到当前对象、当前判断、关键风险和下一步动作；成员明细、证据矩阵、底稿、保存表单、执行编排等低频信息必须在用户显式进入详情后才出现。

本任务覆盖当前 `/asset-decisions` 页面及其自动组、预算压力组、自定义组合、保存记录、场景模板等详情弹层，修复上一轮验证只看文本数量但没有证明实际视觉层级干净的问题。

## Confirmed Facts

- 当前分支从 `origin/main` 创建，页面实现位于 `web/src/pages/AssetDecisionsPage.tsx`，样式位于 `web/src/index.css`，测试位于 `web/src/pages/AssetDecisionsPage.test.tsx`。
- 上一轮已经引入“决策封面”概念，但自动组默认弹层仍展示 4 个事实卡、两个主动作、横向详情导航；自定义组合和保存记录默认弹层也存在类似报告式结构。
- 用户提供的截图显示预算压力组合默认弹层仍像长报告：事实条、场景推进建议、证据矩阵、成员卡、评分、底部表格等内容同时出现，视觉重心混乱。
- 项目规范要求资产决策详情默认层必须是决策封面，不是压缩报告；成员列表、成员姓名、每成员处理按钮、宽表、底稿和说明性长句都应进入二级面板。
- 项目不得新增 Playwright / Cypress / WebDriverIO 等 e2e 依赖；本地浏览器 sanity 只能用现有脚本或 CDP/local-only evidence。

## Requirements

- 自动组详情默认层必须只有一个清晰的决策封面：标题/状态、单句当前判断、最多两个关键风险/缺口信号、一个主动作，以及一个安静的“查看详情”入口。
- 预算压力 / 成本组必须与其它自动组使用同一默认信息架构；不能因为成本数据多而回到成员报告、证据矩阵或多卡片堆叠。
- 自定义组合默认层必须同样只有一个当前判断封面；编辑组合、成员维护、添加成员、另存模板、保存记录、原始底稿只能在显式进入详情后出现。
- 保存记录默认层必须只展示记录状态、执行/跟进判断和主动作；成员跟进、来源复核、执行编排、成员底稿默认不可见。
- 详情能力不能被删除：用户点击“查看详情”后，应能进入原有成员明细、保存记录、编辑/维护、底稿、执行跟进等二级面板。
- 页面列表中的决策组卡片也要降噪：卡片应突出组名、优先级、单句判断、核心风险和一个操作，避免三列事实卡 + 多组 badge 形成小报告。
- 桌面和 390px 移动端打开详情弹层时不得产生页面横向溢出；弹层默认首屏不能被多段报告内容撑满。
- 验证必须包含自动化测试和浏览器可视检查。自动化测试要正向断言默认判断/主动作存在，并反向断言成员名、成员表格、底稿、横向详情导航等默认不可见。

## Acceptance Criteria

- [ ] 自动组默认弹层只渲染一个 `决策封面` 区域；默认不可见 `详情二级面板` nav、`成员明细`、`成员取舍`、`决策组成员对比`、`原始明细`、成员名和每成员 `处理`。
- [ ] 预算压力组默认弹层满足同一条件，并保留创建自定义组合、保存记录或进入详情后的完整能力。
- [ ] 自定义组合默认弹层不显示成员维护、编辑组合表单、添加成员、另存模板、原始明细、成员名和成员意图；点击查看详情后这些能力仍可达。
- [ ] 保存记录默认弹层不显示成员跟进表格、成员底稿、来源复核、执行编排详情和成员名；点击查看详情后原有跟进能力仍可达。
- [ ] 决策组列表卡片不再渲染三块事实卡；每张卡只保留优先级、标题、单句判断、最多两个风险/证据 chip 和 `查看组`。
- [ ] `cd web && npm run test -- --run AssetDecisionsPage.test.tsx` 通过。
- [ ] `cd web && npm run lint`、`cd web && npm run test -- --run`、`cd web && npm run build` 通过。
- [ ] 浏览器 sanity 覆盖桌面和 390px 移动端的资产决策页及预算压力组弹层，记录无横向溢出、默认层视觉清晰、详情在显式点击后出现。
- [ ] 分支通过 PR 合入后，按项目约定监控 PR CI、main CI、Release Please、release/image 发布并验证最终产物。
