# Asset decision modal density audit

## Goal

彻底降低 `/asset-decisions` 资产组合决策页面中所有详情弹窗和二级面板的信息密度，让用户打开任意组、记录、模板或来源复核时都先看到清晰的判断入口，而不是被长篇说明、证据报告、成员事实、表单和操作按钮同时淹没。

本任务是上一轮 `07-01-asset-decision-workbench-deep-clean` 的缺陷延续。截图证据 `/home/murray/.codex/attachments/17ffe930-1848-4cf8-ab30-2f74f10adef4/image-1.png` 显示：打开“预算压力与弱承载”组后，弹窗仍然在一个滚动面板里堆叠顶部摘要、场景建议、证据矩阵、成员大卡、保存/创建动作和底部成员表，整体仍像报告页而不是决策工作台。

这不是截图中单个组的问题，而是资产决策详情层的通用信息架构问题。

## Requirements

1. 全面审查并重构资产决策页面所有详情弹窗路径：
   - 自动组：`overview` / `directory` / `members` / `save` / `raw` / `vps`
   - 自定义组合：`overview` / `directory` / `edit` / `members` / `add` / `save` / `raw`
   - 场景模板：`overview` / `directory` / `create` / `members` / `status`
   - 保存记录：`overview` / `execution` / `members` / `source` / `raw`
   - 单台处理弹窗和组内嵌入处理面板
2. 弹窗必须按“判断入口 -> 单一任务面板 -> 低权重底稿”的层级呈现：
   - 默认层只保留当前判断、关键状态、1 个主动作、1 个查看详情入口。
   - 目录层只给出入口，不展开任何成员、表单或底稿。
   - 任一正式面板同一时间只承载一个任务，不混放证据报告、成员处理、保存记录、底稿表格和说明文。
3. 自动组二级面板必须从“报告式长内容”改成“任务式短内容”：
   - 成员面板只展示可扫描的紧凑行或矩阵，不展示多段解释性文案。
   - 保存记录面板必须先显示最少必要字段，成员理由编辑不得在首屏铺满所有成员。
   - 底稿表格保留，但只能作为低权重显式入口。
4. 自定义组合、模板、保存记录必须同步降低密度，不能只修截图中的预算压力组。
5. 文案必须收敛：
   - 删除或压缩“作为场景启动器”“只读派生”“重新读取当前事实”“不会修改...”等反复解释型文字，除危险确认和错误状态外，不应在普通面板里铺陈说明。
   - 面板标题、按钮、badge 和短状态即可表达含义时，不再附加长句。
6. 现有写入能力必须保留：
   - 创建自定义组合
   - 保存自动组/自定义组为决策记录
   - 编辑自定义组合
   - 添加/移除自定义组合成员
   - 另存模板
   - 创建模板组合
   - 更新模板状态
   - 更新保存记录状态和成员跟进
   - 组内单台 VPS 决策处理
7. 不改变后端 API、数据库 schema、路由 contract 或新增前端依赖。
8. 视觉必须保持候风现有暗色优先、高密度工程工具风格，使用现有 CSS tokens、BEM 和 atoms。

## Acceptance Criteria

- [ ] 打开任一自动组，包括成本/预算压力类组和非成本组，默认弹窗不出现成员姓名、成员说明、数据底稿、保存表单、执行编排或长报告段落。
- [ ] 点击任一自动组 `查看详情` 后，仍不会立即出现成员列表、保存表单、底稿表格或单台处理面板；用户必须再显式选择一个任务入口。
- [ ] 自动组 `members` 面板首屏只显示紧凑成员判断，不出现顶部证据矩阵、场景建议、完整成员报告卡和底部原始表格的同屏堆叠。
