# Focused production operations contracts

This digest stays below Trellis context-injection limits. Before generating or executing any host script, the implementer and reviewer must still read the complete, current versions of `center-compose-upgrade-rollback.md` and `agent-canary-upgrade-rollback.md`; neither truncated injection nor this digest is an executable command sheet.

## Shared shell and evidence rules

- Host scripts are generated only after exact host, path, architecture, release SHA/digest and marker identities are frozen. Direct shebang invocation is forbidden: a SHA-frozen root wrapper uses `env -i` plus absolute `/bin/bash --noprofile --norc`, acquires one canonical root-owned host-wide `flock` before any rollout write, passes the inherited descriptor explicitly, rejects concurrent updater/rollout jobs, and holds the lock through child exit, receipt publication and cleanup. Each child mechanically verifies the descriptor's canonical path/device/inode/owner/mode and calls nonblocking `flock` before proceeding. Scripts use `set -Eeuo pipefail` so `ERR` reaches helper functions, plus explicit `INT=130`/`TERM=143` handling. Every mutating handler checks the frozen root `BASHPID`; inherited traps in command substitutions/subshells return the original status without mutation, and only the root handler performs recovery. Failure injection asserts exactly one recovery per cutpoint and proves hostile `PATH`/`BASH_ENV`/`ENV`/`CDPATH` cannot alter execution.
- Every marker is published only after payload files and directories are synchronized, then the temporary marker is synchronized, atomically renamed and its directory synchronized. Error cleanup removes any complete marker and synchronizes the directory. A missing marker always blocks promotion.
- Whenever a phase claims a successful script exit, the lock-holding root wrapper must directly observe child status `0` and only then atomically publish a `0600` execution receipt binding host/machine, lock identity, canonical child-script path+SHA, exact marker path+SHA and `exit_status=0`. The marker cannot bind a future receipt, so the receipt binds the marker; the next go/no-go requires and reparses both. Center cold backup, Center cutover, Agent backup and Agent supervisor use four separate exact receipt identities.
- Root-only logs may contain private operational diagnostics. Shared task/CI evidence contains only approved digests, versions, counts and statuses; no raw `.env`, Settings, installer command, token, webhook, payload or production log content.
- The continuous A-D authorization never includes deletion of a cold backup, Agent rollback bundle or production failed-state quarantine. Each needs separate explicit path-bound deletion approval.

## Center cold point and cutover

- Production is frozen as `hostcram:/root/data/docker_data/houfeng`, v0.79.4/0062/revision 1 with the exact old Houfeng, PostgreSQL and ClamAV image IDs. The local Docker unix socket, socket metadata, daemon ID/OS/architecture and empty root-owned client config are also frozen; every direct Docker and Compose call uses that single explicit daemon closure and ignores caller contexts/`DOCKER_*`. The fixed target is exact v0.79.6; direct v0.79.5 remains forbidden.
- Every production Compose render/ps/down/up/exec uses `env -i`, one explicit archived `.env`, and the exact common plus proxy-host `-f` files. Inherited `COMPOSE_*`, Telegram, public URL, attachment, comparison or other interpolation values cannot override the recovery point. Dummy tests inject them and prove the rendered source closure is unchanged or fails closed without storing rendered secrets.
- A SHA-frozen private verifier compares every configured service to its live container by exact image plus normalized source/target/type/read-only/propagation/options, full direct environment semantics and the six environment-backed secret bytes without emitting values. It rejects named/unknown mounts, `.env` drift, mixed images and orphans. Every persistent source is contained in the archive and recursively free of symlinks/special files/nested mounts. A canonical uid/gid/mode/ACL/xattr digest including roots and empty directories is rederived from the tar; the marker binds closure/metadata/verifier/image-provenance receipts and hashes both proxy overlays.
- Capacity covers a cold tar, an additional restored deployment, all three saved old images, the fixed image, 25% headroom and 1 GiB. Different filesystems require separate calculations.
- The cold stop/tar/restart critical section is capped at 30 seconds plus three seconds of kill grace. Successful validation stops at a monotonic 55-second cutoff; only recovery retains the full 85-second total, so normal deadline failure cannot consume its 30-second reserve. PostgreSQL probes also use statement timeout. Recovery reuses exact local old images when possible, otherwise loads the manifest-verified saved images and starts exact old Compose with `--pull never` inside the total deadline. Clone failure injection must prove all measured paths, including kill grace, image load, readiness and first heartbeat, before production.
- Heartbeat recovery freezes the two real MonitoringInstance IDs; no global `count(distinct ...)`. The old 0062 cold-point query takes at most 768 rows through the existing `(monitoring_instance_id, observed_at desc)` index before filtering each identity's post-watermark non-backfilled row. Strict large-history PostgreSQL 16 evidence must reject Seq/Bitmap paths and bound actual rows. Only the post-0063 Agent acceptance reader requires the exact partial `(monitoring_instance_id, received_at desc, id desc)` index and its separate 768-row candidate bound.
- The private verifier is a regular root-owned, SHA-frozen, bounded external script. Only after old version/ledger/head/services/init jobs/two stable heartbeats plus authority/Records/attachment/quiet-window evidence pass may `COLD_BACKUP_COMPLETE` exist. If the full private check fails after explicit runtime checks, a bounded `--runtime-health-only` reproof decides whether the exact healthy old stack remains running or the recovery path must restart it.
- Fixed assets are downloaded and verified outside the production tree. The separate cutover script arms a full-cold-restore trap before the first live asset write, `.env` image pin, write stop, service stop or DB mutation. Failure quarantines the entire failed tree, restores the complete cold tree and all old images, and never deletes either evidence tree. A restore failure is called fail-stopped only after bounded stop/kill plus exact target-inactive/no-partial-authority proof; otherwise it remains unproven and requires service/host isolation. Agent rollout additionally requires the lock-holding wrapper's exact `CENTER_CUTOVER_EXECUTION_RECEIPT`, issued only after true cutover-script exit `0` and bound to the target marker.

## Agent backup, supervisor and rollback

- Before rollout, run `CGO_ENABLED=0 GOOS=linux GOARCH=<amd64|arm64> go list -deps -json ./cmd/houfeng-agent` for both architectures at v0.79.4 and fixed SHA. Freeze the repo-local packages and actually selected Go/Cgo/embed files for all four closures and compare each architecture plus their union. Add the Center installer-command generator, installer, unit/env template, `go.mod`, `go.sum`, `Makefile` and publish workflow. Any source/live semantic drift triggers the isolated nonempty-queue upgrade+downgrade rehearsal.
- Each backup marker binds hostname, machine-id digest, architecture, canonical bundle path, rollback-script path+digest, official old binary/unit hashes, env/token fingerprints, canonical live-parent path/device/owner/mode metadata, effective-unit metadata, canonical state-tree metadata, checksum manifest and Center stable-ID receipt. State-root/descendant mounts are rejected. Before any stage write, rollback groups all target files by target `st_dev`, sums every stage byte plus reviewed headroom per device, and proves same-filesystem paths plus aggregate free capacity. A lock-holding root wrapper must separately observe script exit `0` and publish an atomic backup execution receipt binding its own exact script and marker identities; the supervisor requires both.
- The secret supervisor binds the backup marker+execution-receipt pair, rollback script, architecture-specific fixed binary/unit hashes, fixed source revision, exact secret-command SHA, Center issuance-data-receipt path+digest, existing canonical minisign binary+digest+provenance, and SHA-frozen issuance/fixed-local verifiers. The Center receipt is a root-only data/identity receipt, not a script execution receipt. Its parser binds host/machine/architecture/stable ID/exact v0.79.6/expiry plus the unique HTTPS installer URL, public server URL, release repository, token-stdin/install-missing-deps flags and absence of insecure/conflicting flags without exposing command/token bytes. While still holding the same host lock, the supervisor rehashes both command and receipt and reruns that parser immediately before launch. Missing or unknown minisign blocks rollout; automatic dependency installation is not an authorized production side effect. Existing regular/live-symlink/dangling-symlink log or receipt paths fail before mutation.
- The complete signed download, install and fixed-local/first-live success proof runs under a unique prevalidated systemd transient service with sanitized `env -i`, cgroup v2, `Type=exec`, `ExitType=cgroup`, `RemainAfterExit=yes` and `KillMode=control-group`; hostile manager variables and `sudo use_pty` cannot escape the unit. Immediately before any launch attempt, the supervisor unconditionally freezes an 85-second total deadline plus a 15-second success-validation cutoff, reserving 70 seconds for kill/rollback/receipt/cleanup. Clone timing must prove the real signed path completes the full success closure inside 15 seconds; these reviewed 85/15 values supersede the earlier provisional 80-second draft. Timeout, signal, nonzero exit, inactive service or local mixed state stops and kills the whole transient cgroup. Before dispatch acceptance is established, exact `LoadState=not-found` plus absence of the expected cgroup path proves no installer unit exists; a pre-launch cancellation or explicitly failed dispatch must preserve the old Agent as persisted-enabled and active and must never call its disable/stop path. Once `systemd-run` returns zero or a loaded unit/cgroup is observed, the acceptance latch is permanent; rollback begins only for a loaded exact unit whose `ControlGroup` equals `/system.slice/<unit>` and whose regular readable `cgroup.procs` is empty; later `not-found`, empty/drifted ControlGroup or missing/unreadable/nonempty membership is unproven and requires emergency host isolation. Cgroup termination, local restore, durable local-restore receipt, first accepted five-second heartbeat, verify-local and cleanup share the total clock and complete by 85 seconds, at least fifteen seconds before the current 100-second first-notice boundary.
- Rollback `--verify-only` and restore both receive the same marker path+digest. The script independently requires its own canonical path/digest and the bundle/effective metadata to match that marker; cross-pairing fails before any restore write. If rollback preflight/staging cannot begin while the supervisor is already handling an untrusted installer state, the supervisor separately proves disabled+inactive or performs one bounded containment attempt.
- The final pre-dispatch closure first reruns `--verify-only` to prove the current live old binary, unit, env and token bytes equal the frozen bundle, their owner/mode and effective systemd properties still match, and the service is persisted-enabled and active. After that potentially long check it reruns the SHA-frozen issuance parser to revalidate receipt freshness/expiry and exact command semantics, then rehashes the installer command and issuance receipt one final time. Only after every gate and a final pending-signal check pass does it freeze the 85/15 clocks and immediately invoke `systemd-run`. Any backup-receipt-to-launch drift, expiry during the live-old check or installer/receipt replacement fails without stopping or mutating the old Agent.
- Old files are copied to same-filesystem staging paths, content/owner/mode checked and synchronized. Before the first rename, `systemctl disable` must be followed by systemd-directory synchronization and an exact `UnitFileState=disabled` readback; only then may the service be stopped, inactivity proven and final files atomically renamed. Final files are synchronized before daemon-reload/enable/start.
- Any mutation/local-invariant failure performs a bounded disable/systemd-directory-sync/stop/kill attempt. It never claims fail-stopped success if durable disabled+inactive cannot be proven and never starts a mixed set. After the exact regular non-symlink old set, modes, effective unit, persisted enabled state and active state pass locally, rollback atomically publishes and synchronizes a marker-bound local-restore receipt. Until the in-memory phase advances, the root handler first synchronizes the receipt directory and invokes the same SHA-bound `--verify-local-restore` path; a valid durable receipt plus exact live old state advances to the healthy-old phase instead of stopping the service. Later Center receipt failure leaves that healthy old Agent running; the supervisor revalidates the receipt and live state, emits no rollback marker and blocks promotion.
- The supervisor cannot disarm on `active` alone. Before the 15-second validation cutoff it verifies fixed binary/unit hashes, modes, canonical unit/drop-ins, private token equality and a bounded SHA-frozen local verifier receipt covering buildinfo revision, effective unit/env, endpoint, queue drain and an orchestrator-produced exact-ID first-live Center receipt. The later three-batch receipt and soak remain promotion gates.
- Promotion to the second Agent requires a lock-holding wrapper-created zero-exit supervisor receipt and an atomically synchronized root-only `AGENT_INSTALL_COMPLETE`. The chain binds host/machine/arch/lock, backup marker+execution receipt, supervisor script+exit, installer command+issuance data receipt, minisign provenance, exact fixed release/binary/unit, first-live/fixed-local receipts, Center three-batch receipt and quiet-window receipt. Only backup and supervisor script completion use outer execution receipts; issuance remains a signed/parsed data receipt. The next go/no-go revalidates every exact path, digest, field and current canary health.
- Rollback failure is reported separately and never replaces the selected installer/signal status. During the record-only dispatch window, any recorded INT deterministically selects 130, otherwise TERM selects 143, and that pending signal overrides a later ERR; once a recovery handler begins, it disables recursive ERR and ignores further INT/TERM until its bounded proof completes. Failed markers are removed and their directories synchronized; promotion additionally requires the exact private zero-exit execution receipt, so an unlink/fsync failure cannot make a stale marker authoritative.

## Required pre-production tests

- `bash -n`, ShellCheck, dummy real-Compose render, sanitized-wrapper/host-lock/concurrent-updater tests, hostile caller/Docker environment, minisign/issuance URL+flag trust-root tests, path/symlink failures, producer expected-output-then-nonzero/timeouts, record-only pre-dispatch/during-dispatch/post-return signal cutpoints with rc=0 acceptance publication before pending-signal consumption, explicitly failed dispatch plus exact-not-found/no-cgroup with zero old-Agent disable/stop, during-dispatch loaded/cgroup observation followed by terminate+GC/not-found with acceptance still latched and isolation required, deterministic record-window signal precedence (any INT→130, TERM-only→143, pending signal overrides later ERR), signal exit codes, root recovery count exactly one, marker durability cutpoints and every mutation cutpoint.
- Monotonic worst-case Center and Agent timeout tests, including hung Docker/curl/psql/systemctl, TERM/KILL grace, delayed readiness and first heartbeat.
- Marker/script/bundle cross-pair, metadata/content/mode drift, partial rename, stop failure, enabled+inactive, disabled+active, systemd probe error, local mixed fixed state, Center receipt timeout/mismatch and power-loss-style marker ordering.
- No host mutation until these tests and independent reviews have zero Critical/Important/Minor findings and the user grants the post-planning A-D approval.
