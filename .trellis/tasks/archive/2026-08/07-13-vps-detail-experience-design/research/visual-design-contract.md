## 1. 跨页面视觉规则

- 稳定态不渲染异常标题、空异常卡、禁用异常动作或保留高度；异常块只在事实存在时插入，恢复后从 DOM 与布局移除。
- 中性表面、有限边界和字重建立层级；蓝色只表示当前主操作，绿/黄/红只表示有文字解释的状态。
- 链接、按钮、菜单、可进入卡片在静止态使用文字、边框、末端箭头或稳定图标；hover 只是反馈，不承担发现性。
- 桌面主内容最大阅读宽度保持稳定；长工作区可以更宽，但正文行长不随屏幕无限增长。
- 390px 不是桌面列的逐项堆叠。摘要裁剪、筛选抽屉、材料抽屉、单指标比较和有限最近条目保持原任务优先级。
- DOM、视觉与键盘焦点顺序一致。异步插入异常不抢焦点；modal/drawer 关闭后返回原触发器。

## 2. VPS 概览

### 2.1 桌面稳定态

```text
┌ 身份：名称 / 状态 / provider·region·用途 / 更新时间 ─ [新建记录] [时间线] [管理 ▾] ┐
│ 局部导航：概览 | 活动 | 记录 | 证据                                          │
├ 综合状态 ─────────┬ 监控 ─────────┬ IP 质量 ────────┬ 下次续费 ────────────────┤
├ 最近变化：人工记录与系统活动按真实时间合流 ─────────────────── [查看全部] ─────┤
├ 资产事实：稳定身份与配置；不重复上方状态 ─────────────────────────────────────┤
└ 关联：监控实例 →  订阅 →  服务 →  域名 →；每项有数量/摘要与常驻进入指示 ─────┘
```

### 2.2 桌面异常态

异常块只插在身份头与常规摘要之间：`事实 → 影响 → 证据时间/新鲜度 → 必要处理入口`。它把常规内容向下推，不替换监控/IP/续费等上下文。恢复后该块及其动作完全移除。

### 2.3 390px 顺序

1. 身份、更新时间和三个首层动作；管理动作进入菜单。
2. 实际异常块；无异常时本项不存在。
3. 四项摘要使用 2×2 紧凑网格，不复制桌面全部说明。
4. 最近变化最多显示三项，再进入活动页。
5. 去重后的关键资产事实。
6. 关联对象紧凑入口；不展开完整管理表单。

焦点顺序：返回/面包屑 → 新建记录 → 时间线 → 管理 → 局部导航 → 异常动作（若有）→ 四项摘要入口 → 最近变化 → 关联入口。该顺序与身份头首行操作先于第二行局部导航的 DOM/视觉顺序一致。

## 3. 项目级记录中心与单主体时间线

### 3.1 记录中心桌面

```text
┌ 记录中心 ─────────────────────────────────────────────── [新建记录] ┐
├ 搜索 ─ 类型 ─ 主体/关联 ─ 状态 ─ 负责人 ─ 跟进/行动项 ─ 时间 ─ 版本 ┤
├ [筛选 chip ×]  [仅在有数据时：待跟进 / 受阻 / 临期]                 ┤
├ 类型 │ 标题与命中摘要 │ 主要主体+关联数 │ 状态/跟进 │ 更新时间 │ 材料数 ┤
│ ...  │ ...            │ ...             │ ...       │ ...      │ ...   │
└ 稳定游标分页；无状态类型不渲染“不适用” ───────────────────────────┘
```

390px：顶部保留标题、搜索和新建；筛选进入带已选数量的 drawer；活动 chip 横向可滚动；每条结果只保留类型、标题、主体、实际状态/跟进、更新时间和材料计数，次要字段进入详情。无结果与首次空库是不同空态。

### 3.2 单主体时间线

```text
┌ 主体身份 / 更新时间 / 返回来源 ─────────────────────────────────────┐
├ 概览 | 活动 | 记录 | 证据                                             ┤
├ 来源 / 类型 / 时间 / 版本筛选                                          ┤
├ 时间分段                                                               ┤
│ ○ 人工记录：标题、类型/状态、修订入口                                  │
│ ◆ 系统事实：不可编辑、source 与 event time                             │
│ ▣ 证据：关键指标、实际覆盖、桶宽、观测/捕获时间                        │
│ · 评论/行动项：独立活动                                                │
└ 统一水位和游标；不是多个列表分别截断后拼接 ────────────────────────────┘
```

390px：身份条保持一行主身份；局部导航可横向滚动但当前项可见；筛选为 chip + drawer；时间线卡只保留本类必要字段，证据深度图进入详情。

## 4. 横向比较工作台

### 4.1 桌面

```text
┌ 比较工作台 ─ 主体推荐 / 精确 revision·snapshot ─ 2–6 项选择篮 ─────┐
├ 请求窗口 │ baseline │ actual/common overlap │ 容差 │ 桶宽             │
├ 可比性审查：覆盖、偏移、schema、精度、缺失/截断；先于任何指标          │
├ evidence kind tabs                                                     │
├ 趋势图：在真实数据末端停止，不补零/外推                                │
├ 对齐矩阵：列头含主体、revision/snapshot、实际覆盖、桶数和质量          │
├ 系统可验证差异                                                         │
└ 人工结论 ───────────────────────────────────────────── [保存为记录] ┘
```

记录选择固定 revision；同 kind 多快照要求显式选择；无证据项显示“仅元数据”。`common_overlap` 无真实交集时不显示数值结果。

390px：选择条件折叠为可回看摘要；可比性审查保持在首个指标之前；一次只显示一个 kind/指标；图表单列，矩阵使用有名称的局部横向滚动和 sticky 行标题；保存动作位于人工结论之后，不覆盖内容。

## 5. Markdown 编辑器与证据选择器

### 5.1 编辑器桌面

```text
┌ 返回 │ 当前正式 revision │ 自动草稿状态 ─────────────── [保存为新修订] ┐
├ 标题 / 类型 / 状态 / 影响 / 主体关联 / owner·participants / 跟进 / 可见性 ┤
├ 编辑 | 分栏 | 预览 ─ Markdown 工具栏 ──────────────────────────────────┤
│ 正文编辑/预览                                              │ 材料侧栏   │
│ 结构化 evidence/attachment 引用块                          │ 证据       │
│ 作者判断与系统事实明确分开                                 │ 附件       │
│                                                            │ 行动项/大纲 │
└ 本次保存影响：字段、引用、权限与 revision 变化 ─────────────────────────┘
```

390px：顶部显示返回、revision、草稿状态和保存；元数据分组折叠但错误字段自动展开；正文一次显示编辑或预览；材料、大纲和本次影响进入 drawer，不与正文形成两个窄列。

### 5.2 证据选择器

顺序固定为：kind → source/report/event → 绝对时间窗 → 指标 → 精度 → 敏感字段 → 服务端预览 → 确认。预览必须在确认按钮之前展示实际覆盖、桶宽/桶数/数据点、质量/缺口、schema、预计体积/配额、脱敏与长期留存语义。preview stale 后保留原选择，展示差异并要求再次确认。

## 6. 页面状态矩阵

| 页面 | 初始加载 | 首次空态 | 查询无结果 | 局部失败 | 提交/后台处理中 | 权限撤销/永久删除 |
|---|---|---|---|---|---|---|
| VPS 概览 | 身份骨架先行；摘要骨架不伪造状态 | 不适用；缺来源按局部不可用 | 不适用 | 仅失败区显示原因、最后成功与重试；影响判断时动态插入异常 | 管理动作只锁自身；常规阅读继续 | 统一 404/返回列表；清客户端受管缓冲 |
| 记录中心 | 搜索与筛选可见，结果 skeleton 保持列职责 | 解释用途 + 新建记录，不显示跟进卡 | 保留 query/chip，提供清除筛选 | 结果失败不伪装为空；重试保持 URL | 游标续页显示行内进度，不替换已有结果 | 失权结果从列表移除且不泄露计数 |
| 单主体时间线 | 身份先行，时间线 skeleton | “尚无活动/记录/证据”按当前 tab 精确说明 | 保留筛选并提供清除 | 单来源失败显式标注，不能把其他来源当完整 | projector 延迟显示水位/刷新，不插入假事件 | 主体删除保留身份 tombstone；无权统一 404 |
| 比较 | 选择条件先行；结果区等待 | 少于 2 项时展示选择引导 | 无兼容 evidence 显示原因，不出空图 | 单 snapshot/kind 失败进入可比性告警 | 长比较显示阶段、可取消；旧结果不冒充新条件 | 失权项移除并使比较条件失效 |
| 编辑器 | 先载入权限、revision 与草稿，再开放编辑 | 新记录使用可选模板，不伪造正式 revision | 不适用 | 草稿同步失败保留输入；材料失败只阻止对应引用 | 自动草稿三态与正式保存分离；冲突进入 diff/merge | 立即停止保存并清内存/IndexedDB/object URL |
| 证据选择器 | source/schema 逐级加载 | 无来源/报告/数据分别说明 | 选择无覆盖显示实际空覆盖 | 来源 unstable/stale 保留选择并给稳定错误 | preview/capture 显示阶段和取消；不提前加入记录 | 关闭选择器并清 intent/预览 |

所有 skeleton 使用 `aria-busy`，不以真实绿色状态或“0 条”冒充已加载结果。错误、空态、无结果和无权限具有不同语义与测试 fixture。

## 7. 评审追踪

用户已经通过可视化伴侣分别确认：

1. VPS 概览稳定骨架、异常动态插入和三个首层动作；
2. 项目记录中心与单主体时间线的双入口；
3. 可比性先于指标的横向比较工作台；
4. 全页面 Markdown 编辑器、材料侧栏/抽屉和证据选择器；
5. 稳定态无异常占位、正常内容持续存在、深度任务进入 modal 或独立页的总原则。

实现阶段必须以本 Artifact ID 生成桌面和 390px 的 Playwright 语义、状态、几何、overflow、Axe 与焦点基线，并使用短期未跟踪材料完成人工视觉评审；遵守当前 Web spec，不提交像素 golden、screenshot manifest 或批量 raster。任何区域顺序、空态语义或异常占位变化需要回到设计评审，而不是在组件实现中自行决定。
