### Code Patterns

- `cmd/` is intentionally thin. `main.go` should not contain business logic: it loads config, creates a signal context, calls bootstrap, and handles fatal errors (`cmd/houfeng-center/main.go:15-37`). Directory spec reinforces this: `cmd/` is per-binary entry plus assembly only, and business logic belongs in `internal/center/<domain>/` (`.trellis/spec/backend/directory-structure.md:84-97`).
- There is no existing subcommand dispatcher. Searches found no production `flag.*` or `os.Args` command routing under `cmd/`; adding a JSON import command would be the first CLI/subcommand pattern in `houfeng-center`. Keep parsing minimal and put import behavior outside `cmd/`, with `cmd` only dispatching and wiring.
- Existing bootstrap tests provide the closest `cmd` test pattern: dependency injection through `bootstrapDeps`, assert downstream calls are skipped on early failure, and use `errors.Is` to verify wrapped errors (`cmd/houfeng-center/bootstrap_test.go:23-64`, `cmd/houfeng-center/bootstrap_test.go:67-111`).
- Strict JSON decoding is already an API convention via `DisallowUnknownFields()` (`internal/center/http/handlers/json.go:22-25`). For file import, use the same strictness unless the PRD explicitly wants tolerant import; do not silently ignore unknown fields in dry-run.
- Domain validation should be reused directly:
  - Provider create normalization trims strings and labels; validation requires nonblank `name` and rating `1..5` or null (`internal/center/providers/types.go:129-147`, `internal/center/providers/types.go:184-213`).
  - VPS create normalization trims string fields, normalizes nullable `provider_id`, defaults `renewal_decision` to `unreviewed`, `importance` to `normal`, `ssh_port` to `22`, and de-duplicates labels (`internal/center/vpsassets/types.go:311-341`, `internal/center/vpsassets/types.go:462-477`).
  - VPS create validation requires nonblank `display_name`, valid lifecycle/usage/renewal enums, and SSH port `1..65535` (`internal/center/vpsassets/types.go:345-361`, `internal/center/vpsassets/types.go:479-507`).
  - Subscription create normalization trims `vps_id`, uppercases currency, trims billing/payment/note, and defaults empty status to `active` (`internal/center/subscriptions/types.go:278-288`).
  - Subscription create validation requires nonblank `vps_id`, nonnegative/2-decimal price, positive `billing_months`, uppercase 3-letter currency, and allowed status (`internal/center/subscriptions/types.go:291-307`, `internal/center/subscriptions/types.go:386-424`).
- Existing repositories already run normalization and validation before writing, so real import can call repository methods safely; dry-run should call the same domain normalizers/validators without generating IDs or writing rows unless it needs an exact simulated output (`internal/center/store/providers.go:105-114`, `internal/center/store/vps_assets.go:166-175`, `internal/center/store/subscriptions.go:159-168`).
- ID generation conventions are fixed by aggregate: providers use `ids.New("pv")`, VPS assets use `ids.New("vps")`, subscriptions use `ids.New("sub")` (`internal/center/store/providers.go:111-114`, `internal/center/store/vps_assets.go:172-175`, `internal/center/store/subscriptions.go:165-168`). Dry-run should avoid consuming random IDs unless the task explicitly wants preview IDs.
- Dates for subscriptions are plain calendar dates, not timestamps. `ParseDate` uses layout `2006-01-02`, trims input, and returns `ErrInvalidSubscriptionInput` for invalid strings (`internal/center/subscriptions/types.go:28-35`, `internal/center/subscriptions/types.go:135-140`). `NewDate` normalizes to midnight UTC (`internal/center/subscriptions/types.go:143-146`).
- Money is currently represented as `float64` in the domain, then guarded by `IsValidPrice` to reject NaN/Inf, negative values, values above `9999999999.99`, and more than 2 decimals (`internal/center/subscriptions/types.go:39-46`, `internal/center/subscriptions/types.go:402-467`). `monthly_price` is backend-derived and rounded to 4 decimals (`internal/center/subscriptions/types.go:419-424`).
- Database constraints mirror domain validation and should be treated as a second line of defense, not the primary dry-run validator:
  - Provider name/rating constraints (`db/migrations/0016_create_asset_ledger.sql:1-14`).
  - VPS provider FK, lifecycle/usage/renewal enum checks, SSH port range (`db/migrations/0017_add_vps_assets.sql:1-38`).
  - Subscription VPS FK, `numeric(12,2)` price, positive billing months, uppercase 3-letter currency, allowed status (`db/migrations/0018_add_subscriptions.sql:1-21`).
- FK/check database errors are mapped to invalid input for VPS and subscriptions by `pgconn.PgError` code `23503` or `23514` (`internal/center/store/vps_assets.go:369-375`, `internal/center/store/subscriptions.go:298-304`). Dry-run cannot rely on DB FK errors unless it queries existing records or uses the real write path inside a rolled-back transaction.
- The existing store layer has no multi-record Asset Ledger import transaction. Single-record repositories use `QueryRow` directly. The spec says multi-table writes should use a transaction template with begin, deferred rollback, commit, and `%w` wrapping (`.trellis/spec/backend/database-guidelines.md:35-55`). For a real non-dry-run import that creates provider/VPS/subscription records as one unit, add a transaction boundary instead of calling three repositories independently if partial writes are unacceptable.
- Existing transaction precedent is `PostgresSyncRepository`, where a transaction spans validation, heartbeat/observation inserts, state advancement, and plan building (`.trellis/spec/backend/database-guidelines.md:14-29`, `.trellis/spec/backend/database-guidelines.md:35-55`). Asset Ledger import should follow this shape if it writes related rows atomically.
- Error handling conventions require sentinel errors in domain packages, `%w` wrapping, `errors.Is`, no string comparisons, and no `panic` in production `internal/`, `agent/`, or `cmd/` code (`.trellis/spec/backend/error-handling.md:14-56`, `.trellis/spec/backend/error-handling.md:59-79`, `.trellis/spec/backend/error-handling.md:129-149`).
- Handler-style output maps validation failures to short `"invalid input"` / `"invalid json"` messages and hides raw internal errors (`internal/center/http/handlers/providers.go:21-43`, `internal/center/http/handlers/vps.go:36-58`, `internal/center/http/handlers/subscriptions.go:32-54`). A CLI import can be more detailed for row diagnostics, but should still avoid leaking secrets and should preserve wrapped errors internally.
- Store tests do not use real Postgres; spec says all `internal/center/store/*_test.go` currently use fake pgx row/tx implementations (`.trellis/spec/backend/quality-guidelines.md:155-165`). Import tests should prefer pure parser/validator tests plus fake repositories/transactions unless an explicit `_e2e_test.go` is added and skipped without env.
- Verification expected after implementation: `make verify-go` always, or `./scripts/verify.sh` only if web changes are included (`.trellis/spec/backend/quality-guidelines.md:22-39`, `.trellis/spec/backend/quality-guidelines.md:218-227`, `Makefile:63-73`).

## Caveats / Not Found

- No `prd.md` exists in `.trellis/tasks/05-09-vps-json-import-dry-run/` at research time; scope was inferred from task metadata and the dispatch prompt. `implement.jsonl` still contains only the seed `_example` row (`.trellis/tasks/05-09-vps-json-import-dry-run/implement.jsonl:1`).
- No existing production CLI subcommand, `flag` usage, JSON file import, or dry-run command pattern was found under `cmd/`, `internal/`, or `agent/`. Any subcommand shape for `houfeng-center` will be new.
- No delete/import/upsert semantics exist for Asset Ledger providers/VPS/subscriptions. Current repositories only support list/get/create/patch (`internal/center/providers/types.go:67-72`, `internal/center/vpsassets/types.go:177-182`, `internal/center/subscriptions/types.go:128-133`).
- Provider uniqueness is not enforced by schema beyond `provider_id`; `providers.name` only has a lower-name index, not a unique constraint (`db/migrations/0016_create_asset_ledger.sql:1-40`). Import matching by provider name would be a new product decision.
- `vps_assets` has no unique key on order reference, IP, SSH host, or display name (`db/migrations/0017_add_vps_assets.sql:1-97`). Duplicate detection for import is therefore not available from the existing schema.
- `subscriptions.monthly_price` is rounded to 4 decimals by Go on create, but SQL patch recomputes division in the database without explicit `round(..., 4)` (`internal/center/subscriptions/types.go:419-424`, `internal/center/store/subscriptions.go:243-249`). Avoid creating a separate import-side monthly-price formula; either call existing helpers or record this as a follow-up if exact patch/create parity matters.
- Current repository constructors require `*pgxpool.Pool`, while their structs hold small internal DB interfaces (`internal/center/store/providers.go:17-28`, `internal/center/store/vps_assets.go:19-29`, `internal/center/store/subscriptions.go:20-30`). If import code needs transaction-backed repositories, it may need a small internal constructor/interface adjustment, kept in `internal/center/store/`.
- Asset Ledger specs explicitly forbid provider/VPS/subscription CRUD from rewriting Fleet Observability `nodes.provider`, creating `vps_node_links`, changing Node/Target/Agent semantics, or adding Dashboard/import/currency-exchange behavior beyond the task (`.trellis/spec/backend/database-guidelines.md:108-143`). Import implementation should stay within VPS JSON import and not expand those surfaces.
