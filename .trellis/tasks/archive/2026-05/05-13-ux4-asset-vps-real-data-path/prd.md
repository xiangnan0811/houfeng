# UX-4 Asset Decision and VPS Inventory Real-Data Path

## 背景

UX-3 已把 Dashboard 的命令入口和深链路径推进到可用状态。下一步 UX-4 要承接真实数据验证：用户需要愿意把 40+ 台 VPS 录入系统，并能从 `Asset Decisions` 与 `VPS` 页面快速判断哪些资产必须处理、哪些信息只是证据不可用、哪些资料缺口需要补齐。

当前页面已经具备基础队列、筛选和详情抽屉，但真实数据验证前仍需要加强两点：

- 资产决策页必须更像一个处理队列，而不是静态列表。用户进入页面后应立刻知道先处理续费窗口、未决策、迁移/退役、缺订阅、未关联 Node、资料缺口中的哪一类。
- VPS 页必须能承载 40+ 行高密度资产盘点。订阅数据读取失败时不能把所有 VPS 误呈现为“缺订阅”；只有订阅接口成功返回且某台 VPS 没有订阅时，才允许显示真实的缺订阅事实。

## 目标

1. 强化 `AssetDecisionsPage` 的决策队列引导，让优先级、资料缺口、生命周期动作和续费证据在首屏可扫。
2. 强化 `VPSPage` 的真实数据盘点路径，让 40+ 行列表在筛选、排序、证据状态和详情入口上保持清晰。
3. 修复 VPS 页面订阅证据状态表达：订阅接口失败或加载中时显示“订阅未知/证据不可用”，不得计入或渲染为真实“缺订阅”。
4. 保持 Dashboard 深链连续性。已有 URL view/filter/drawer 状态应继续可见、可操作、可被下一次交互写回合法查询参数。
5. 更新 UI 演进路线文档，记录 UX-3 已完成并把 UX-4 当前变更及后续 UX-5 方向写清。

## 非目标

- 不改后端 API、数据库 schema、资产模型或认证模型。
- 不引入新的前端状态库、数据缓存库、图表库或表格库。
- 不在 VPS 列表里显示已关联 Node 的健康状态；仅允许显示关联数量/未关联状态。
- 不把该任务扩展成全站视觉重做；仅围绕 Asset Decisions 与 VPS 的真实数据路径。

## 需求

### Asset Decisions

- 首屏保留现有统一工作队列，并增加更明确的处理焦点摘要。
- 焦点摘要至少覆盖：
  - 需要优先处理的续费窗口内未决策资产。
  - 缺订阅、未关联 Node、资料缺口等数据治理项。
  - 迁移/退役等生命周期动作。
  - 续费窗口证据来源。
- 队列优先级继续使用现有业务规则，不因视觉重排改变排序含义。
- 订阅列表整体读取失败时，不应把全部 VPS 误报为缺订阅；页面应显示队列错误或证据不可用状态。

### VPS Inventory

- 保留现有 quick views、筛选抽屉、表格和行级详情入口。
- 增加面向 40+ 行真实数据的盘点焦点摘要，例如当前可见行数、续费窗口、未决策、资料缺口、订阅证据状态。
- 订阅证据状态必须分离：
  - `ready`：订阅请求成功，可把无订阅 VPS 渲染为真实“缺订阅”。
  - `loading`：订阅证据加载中，暂不把任何 VPS 计为“缺订阅”。
  - `error`：订阅请求失败，显示“订阅未知/证据不可用”，暂不把任何 VPS 计为“缺订阅”。
- `missing_subscription` quick view 只有在订阅证据 `ready` 时才显示真实计数；证据不可用时应给出明确提示。
- 现有 `unlinked`、`missing_facts`、`renewal`、`unreviewed` 等视图继续基于 VPS 与已知字段工作。
- 不展示 Node 健康状态，仅展示关联数量或未关联风险。

### 文档

- `docs/release/ui-evolution-roadmap.md` 应反映 UX-3 已通过 PR 完成。
- 文档应说明 UX-4 进入/完成状态，以及 UX-5 的下一阶段方向。

## 验收标准

- `AssetDecisionsPage` 和 `VPSPage` 在桌面首屏都能直接回答“现在最应该处理什么”。
- VPS 页面在订阅接口失败时仍能展示 VPS 列表主体，并显示订阅证据不可用；不得出现把所有 VPS 当成真实缺订阅的视觉或测试行为。
- VPS 页面在订阅接口成功但返回空列表时，仍能把无订阅 VPS 显示为真实缺订阅。
- URL 中不支持的 view 会回退为 `all`，后续交互写回合法 query。
- 补充针对订阅证据失败/缺订阅真实状态的前端测试。
- 运行前端测试、lint/type-check/build；若仓库已有全量脚本可用，按现有命令验证。
- 生成桌面和移动视觉证据，覆盖 `/asset-decisions` 与 `/vps`。
