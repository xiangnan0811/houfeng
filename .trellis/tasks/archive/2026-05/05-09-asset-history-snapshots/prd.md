# asset history snapshots backend

## Goal

Continue the planned Task 8 history work by completing the remaining backend history surfaces for Asset Ledger: price history, IP history, VPS specification snapshots, and the existing VPS timeline API aggregation.

## Scope

- Add the next migration after `0020_create_renewal_decisions.sql` for:
  - `price_histories`
  - `ip_histories`
  - `vps_spec_snapshots`
- Extend the existing `internal/center/renewals` timeline domain to include those history records.
- Extend the existing timeline repository so `GET /api/vps/{vps_id}/timeline` returns:
  - `renewal_decisions`
  - `price_histories`
  - `ip_histories`
  - `spec_snapshots`
- Record `price_histories` when a subscription PATCH changes price, currency, billing cycle, billing months, renew date, auto-renew flags, or status.
- Record `ip_histories` when VPS PATCH changes `ipv4` or `ipv6`.
- Record `vps_spec_snapshots` when VPS PATCH changes spec-like fields: `product_name`, `ssh_host`, `ssh_port`, `ssh_user`, `os_name`, or `virtualization`.
- Keep all writes in the same transaction as the current-state PATCH when a history record is needed.
- Update backend Trellis specs to record the new history contract.

## Non-Goals

- Do not process real VPS JSON data in this task.
- Do not add the frontend decision page.
- Do not add UI timeline rendering.
- Do not add provider API sync, DNS sync, Web SSH, plugin behavior, service discovery, or Agent-side asset logic.
- Do not alter Node, Target, Agent, or `nodes.provider` semantics.

## Requirements

- History tables must use stable text IDs generated by `ids.New`.
- History rows must reference existing asset-layer entities and cascade with the owning VPS or subscription.
- Timeline lookup must continue to return 404 for missing VPS assets.
- Timeline lookup must reject blank VPS IDs as invalid input.
- No placeholder or fake history arrays are allowed; the API must return real table-backed arrays.
- Current-state updates and related history inserts must be atomic.
- Unchanged values must not create history noise.
- Database/API values remain stable machine values; Chinese display labels remain a frontend concern.

## Acceptance Criteria

- [x] Migration defines `price_histories`, `ip_histories`, `vps_spec_snapshots`, constraints, and timeline indexes.
- [x] Subscription PATCH records one price history row when tracked billing/renewal fields change.
- [x] Subscription PATCH does not record price history when tracked fields are unchanged or patch is a no-op.
- [x] VPS PATCH records IP history when IPv4 or IPv6 changes.
- [x] VPS PATCH records a spec snapshot when tracked spec fields change.
- [x] VPS PATCH does not record IP/spec history for unchanged tracked values.
- [x] `GET /api/vps/{vps_id}/timeline` includes the three new history arrays plus existing renewal decisions.
- [x] Existing renewal decision history behavior remains intact.
- [x] Existing Asset Ledger CRUD, Dashboard, Node, Target, and Agent tests remain green.
