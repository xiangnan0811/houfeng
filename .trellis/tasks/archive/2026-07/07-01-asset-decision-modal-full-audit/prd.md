# 全面收敛资产决策弹窗信息架构

## Goal

资产组合决策页的弹窗必须从“报告塞进 modal”重构成清晰的渐进披露工作流。用户打开任一组合、模板或保存记录时，第一眼只能看到当前对象、判断、少量风险信号和下一步动作；成员、底稿、执行编排、来源回读、保存表单等内容必须在用户显式进入二级面板后出现。

本任务承接用户对页面混乱、三屏堆叠、解释性文字过多、像本科答辩 PPT 的反馈。截图证据位于 `/home/murray/.codex/attachments/17ffe930-1848-4cf8-ab30-2f74f10adef4/image-1.png`，显示“预算压力与弱承载”组弹窗仍像报告而不是决策封面。

## Requirements

- 覆盖 `/asset-decisions` 中所有资产决策详情弹窗：
  - 自动组详情，至少包含预算/成本压力组和非成本组。
  - 自定义组合详情。
  - 场景模板详情。
  - 已保存组合决策记录详情。
- 默认层必须是“决策封面”：
  - 只展示标题/状态、紧凑事实条、单句判断、最多 1-2 个风险/缺口信号、主动作和“详情”入口。
  - 不展示成员姓名、成员列表、成员摘要、每成员操作、保存表单、执行编排、来源回读、宽表、原始底稿、证据矩阵、取舍对比、旧解释标题或长段落。
  - API 返回的长 `summary`、`goal`、`note`、`comparison_insight.summary`、`decision_recommendation.summary` 不得直接撑开默认层。
- `详情` 首跳必须进入短目录，不得直接展开成员、底稿、保存表单或处理面板。
  - 目录项只允许 label、count/status 和极短 meta。
  - 目录项不得包含成员名、内部 ID、字段解释、完整说明句、宽表线索或来源回读长文本。
- 二级面板必须是单任务短面板：
  - 成员面板只展示姓名、角色、动作、一句判断、少量信号和必要动作；不得展示 provider/product/cost/facts 串或证据矩阵。
  - 保存面板只展示基础字段与成员复核行，逐个成员展开编辑。
  - 记录执行面板只做状态推进和执行跟进，不复用保存依据或来源回读。
  - 来源面板只做来源复核入口，不展示完整报告。
  - 底稿/宽表只在显式选择底稿面板后出现，并允许表格内部横向滚动。
- 页面视觉必须条理清晰、主次分明、工程工具感克制，不新增营销式/装饰性布局，不用卡片套卡片。
- 桌面和 390px 移动端打开典型弹窗后，`document` / `body` 不得出现横向溢出；modal 内表格横向滚动允许。
- 必须补强测试，使回归不依赖某几个旧标题：
  - 对默认层建立可见文本密度、禁止结构和禁止 marker 的泛化断言。
  - 对详情目录建立短 meta 和禁止解释句的断言。
  - 覆盖自动预算/成本组、自动非成本组、自定义组合、模板、保存记录。
- 不改变后端 API 合同，不发明资产决策语义，不自动执行迁移/取消/续费等危险动作。

## Acceptance Criteria

- [ ] `AssetDecisionsPage.test.tsx` 有失败再通过的回归测试，覆盖上述四类弹窗及成本/非成本自动组。
- [ ] 默认层测试断言成员名、成员表格、底稿、保存表单、执行编排、来源复核、长报告 marker 均不可见。
- [ ] 目录测试断言目录项元信息短、无内部 ID、无 provider/product/cost/facts 串、无说明句。
- [ ] 实现中统一限制默认封面文案长度，避免数据源长文本撑开首屏。
- [ ] `cd web && npm run test -- --run AssetDecisionsPage.test.tsx` 通过。
- [ ] `cd web && npm run lint` 通过。
- [ ] `cd web && npm run build` 通过。
- [ ] 使用浏览器或 `scripts/visual_evidence.py browser-sanity` 检查 `/asset-decisions` 桌面和 390px 移动端典型弹窗，无横向溢出且默认层不再像报告。
- [ ] 任务完成后按项目约定提交、推送分支、创建 PR，并监控 PR CI；如合并触发 Release Please / 发布镜像，继续跟进到相关自动化有明确结论。

## Out of Scope

- 不新增后端字段或修改资产决策算法。
- 不引入新的前端状态库、CSS 框架或 e2e 依赖。
- 不把低频深度报告迁移到新页面；本任务只收敛现有弹窗的信息架构。

## Notes

- 当前源码已经移除了截图中的若干旧标题（如“场景推进建议”“证据矩阵 / 取舍对比”），但这不足以证明用户问题解决。风险在于运行时缓存/部署、数据驱动长摘要、漏掉的 modal 入口、以及测试只覆盖旧 marker。
