# Asset decision workbench deep clean

## Goal

资产组合决策页仍然没有达到用户要求。最新截图显示用户打开某个自动组时，弹窗仍然像报告/PPT：大量说明、矩阵、成员大卡、标签、表格和多个动作同时出现，用户无法快速判断重点。这次返工必须以当前 worktree 和真实页面行为为准，全面审查 `/asset-decisions` 的所有组、记录、模板和二级入口，解决“默认打开就进入长报告”的根因。

成功标准不是几个旧标题消失，而是：用户打开任意资产决策对象时，默认视图只回答“对象是谁、当前判断是什么、最关键的风险是什么、下一步主动作是什么”，其它内容必须进入明确的二级面板。

## Confirmed Facts

- 当前分支：`ux/asset-decision-workbench-deep-clean`，从 `main` / `v0.56.5` 创建，工作区初始干净。
- 当前源码 `web/src/pages/AssetDecisionsPage.tsx` 已经没有截图中的旧标题 `场景推进建议`、`证据矩阵 / 取舍对比`，但截图暴露了更大的验收缺陷：上一轮只证明旧 marker 消失，没有证明默认信息架构真正干净。
- 当前自动组 modal 默认使用 `groupDetailPanel === 'overview'` 展示封面；点击 `查看详情` 会直接切到 `members` 并渲染完整 `renderMemberDecisionCards`，其成员大卡包含名称、角色、动作、成本、承载、监控、状态、证据源、强项、风险、多个 chip 和处理按钮，仍然接近长报告。
- 当前二级面板是 tab nav + 大区块内容，缺少“详情目录 / 单面板渐进披露”的中间层；用户从默认态一步进入完整成员报告，视觉跳变太大。
- 历史归档任务中曾把“默认显示关键成员摘要和处理入口”列为验收项，这是错误方向，会把默认弹窗重新推回报告态。
- 项目规范已明确：资产决策详情默认层必须是决策封面，不是压缩报告；成员列表、成员姓名、处理按钮、保存表单、执行编排、来源回读、宽表、原始底稿和说明性长句默认不可见。
- 不允许为这次返工新增 Playwright/Cypress/WebDriverIO 或其它 e2e 依赖；浏览器验证使用本地 CDP/现有 helper，并把截图/脚本保留在 ignored 临时目录。

## Requirements

- 审查范围必须覆盖所有资产决策详情入口：
  - 自动组：needs_decision、renewal、region、provider、cost、evidence、cancellation 等代表组；
  - 通过顶部 current judgment / next-work 打开的组；
  - 通过组列表 `查看组` 打开的组；
  - 通过 URL `group_id` deep link 打开的组；
  - 自定义组合、保存记录、场景模板；
  - 保存记录来源复核再打开的组。
- 默认打开任何自动组时，只能显示：
  - 组名和极短状态；
  - 单句当前判断；
  - 最多 1-2 个风险/缺口 chip；
  - 一条低噪声事实 footer（例如成员数、视图、月成本）；
  - 一个主动作和一个进入详情的安静入口。
- 自动组默认态不得显示：
  - 成员姓名 / VPS ID / 单台信息；
  - 每成员 `处理`、`VPS`、`取消/退役` 等动作；
  - 成员大卡、成员摘要、成员列表；
  - 保存记录表单或 `保存为决策记录` 按钮；
  - 原始表格、宽表、数据底稿；
  - 证据评分刻度、完整证据矩阵、完整推荐 reasons/blockers；
  - 解释性长句、英文 section eyebrow、报告式标题。
- 点击 `查看详情` 后不得直接把完整成员报告铺开。详情首层应先进入“详情目录/二级工作台”，每次只显示一个明确面板，且默认面板仍要轻量。
- 成员详情面板必须降噪：优先展示少量“成员决策行”或紧凑列表，而不是每台一个四事实区 + 两组信号 + 多 chip 的大卡。完整事实、处理动作和底稿只能继续下钻或在更低权重面板中出现。
- 保存记录、成员维护、原始底稿、单台处理、执行跟进、来源复核、模板创建等能力必须保留，但只能通过显式二级入口出现。
- 自定义组合、保存记录和模板默认态也必须满足同一信息预算，不能用“不是截图对象”作为排除理由。
- 页面主体也要审查是否仍有“报告式说明/卡片堆叠”导致重点不清；若存在同类默认噪音，应同步修复或在设计中明确为何不是本轮问题。
- 证据表达必须诚实：预算压力、弱承载、缺证据、退役/取消风险不能被隐藏成稳定；降噪是减少承载形态，不是删除风险。
- 不改后端 API、数据库 schema 或新增前端依赖。

## Acceptance Criteria

- [ ] 形成当前页面审计记录，覆盖代表性自动组、自定义组合、保存记录、模板和来源复核入口，列出每个默认态/详情态的噪音来源。
- [ ] 自动组从所有入口默认打开时，`dialog.innerText` 不包含成员姓名/VPS ID、`处理`、`VPS` 单台动作、`保存为决策记录`、`成员取舍`、`成员明细`、`数据底稿`、`证据评估刻度`、宽表列头或旧报告标题。
- [ ] 自动组默认态可见内容只包含组名、当前判断、最多少量风险 chip、紧凑 meta、`创建自定义组合` 和 `查看详情`。
- [ ] 点击 `查看详情` 后先出现二级导航/详情目录，默认不一次性展开完整成员大卡、保存表单、原始表格或单台处理面板。
- [ ] 成员面板降噪为可扫描的紧凑决策列表；完整事实/处理动作仍可通过明确入口到达，且原有写 API payload 不变。
- [ ] 预算压力组、非成本自动组、自定义组合、保存记录、模板详情均有自动化测试覆盖默认信息预算和二级能力保留。
- [ ] 浏览器验证覆盖桌面 `1440x1000` 和移动 `390x900`，至少打开 cost + needs_decision + evidence/region/provider 中一个非成本组，以及 record/manual/template；无 document/body 横向溢出，默认视图不是长报告。
- [ ] 本地质量门通过：`git diff --check`、`cd web && npm run test -- --run AssetDecisionsPage.test.tsx`、`cd web && npm run lint`、`cd web && npm run test -- --run`、`cd web && npm run build`。
