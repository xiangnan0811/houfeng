# 资产组合决策页面全面体验审计与重构

## Goal

彻底完成 `/asset-decisions` 资产组合决策页面的第二轮全面审计与必要重构，让页面成为真正可用的组合决策工作台，而不是解释文字、证据、成员、表格、表单和底稿混排的报告页。

最终体验目标：

- 功能完整：用户能完成自动组判断、自定义组合、场景模板、保存记录、执行跟进、来源复核和单台辅助处理的现有工作流。
- 主次清晰：默认页面和弹窗第一眼只回答“现在要不要决策、最该处理什么、下一步做什么”。
- 视觉克制：去掉可有可无的解释、英文 eyebrow、重复状态和同权重辅助区，保留安静、密集但有秩序的操作界面。
- 不打扰：当前没有需要决策、漂移、阻塞或资料缺口时，页面应呈现低权重的稳定/空状态，不制造紧张感，不用大面积 CTA 打扰用户。
- 运行可信：修改必须通过测试、构建、浏览器截图和手工视觉审查，不能只依赖“旧 marker 不出现”。

## Requirements

### Confirmed Facts

- 当前分支为 `ux/asset-decisions-comprehensive-review`，非 `main`；本任务处于 Trellis `planning`。
- 当前实现仍集中在 `web/src/pages/AssetDecisionsPage.tsx`，约 6079 行；测试集中在 `web/src/pages/AssetDecisionsPage.test.tsx`，约 2617 行。
- 前序 PR #319 已合并并发布 `v0.56.11`，实现过一轮弹窗密度收敛，但 persistent goal 仍未完成，原因是没有在本轮重新基于最新运行态做全路径视觉验收。
- 历史任务与规范已经确定资产决策详情应遵守 `Cover -> Directory -> Task Panel -> Raw`：默认层是决策封面，详情先进入目录，二级面板单任务，底稿独立承载宽表和长事实链。
- 当前代码已有 `overview` / `directory` / 任务面板状态，但页面主区仍包含 `PORTFOLIO`、`RENEWAL`、`CLOSED LOOP`、`EVIDENCE`、`PORTFOLIO WORKBENCH` 等英文 eyebrow，以及场景、记录、续费、单台辅助区的解释文字；这些需要审计是否仍造成中英文混杂和视觉噪音。
- 用户明确要求：暂不做完整 i18n 体系；本页面本轮只要求用户可见文案显示中文，后续再考虑完善 i18n。
- 用户已授权本任务及后续类似 UI/IA/视觉层级任务直接使用可视化 companion；该偏好已写入 `.trellis/spec/web/component-conventions.md`，以后不需要重复询问是否启用。
- 用户已确认本任务采用 “A：先审计真实页面，再画方案” 的节奏；先以当前运行态找出所有仍然混乱的路径，再做针对性 mockup 和技术设计。
- 用户已确认页面主体设计基准采用 “A：决策优先，稳定静默”：有问题时只突出一个主判断和决策组扫描；无问题时显示低干扰状态，模板、历史、续费事实和单台队列只作为辅助入口。
- 用户已确认辅助入口采用 “A：紧凑工具条”：桌面低权重一行展示，移动端 2x2 小入口；点击后展开对应次级工作台。不要把这些入口藏进单一“辅助工具”菜单，也不要恢复四张同权重解释卡。

### Functional Scope

1. 审计并必要时重构资产组合决策页面主体：
   - 顶部当前判断 / 主工作项。
   - 决策组扫描列表。
   - 次级入口：场景、自定义组合、保存记录、续费事实、单台辅助队列；入口默认为紧凑工具条，只有用户点击或深链命中时才展开对应工作台。
   - 加载、空状态、错误状态、深链承接状态。
2. 审计并必要时重构所有详情弹窗路径：
   - 自动组：预算/成本组以及至少两个非成本自动组。
   - 自定义组合：默认层、目录、编辑、成员、添加成员、保存记录、底稿。
   - 场景模板：默认层、目录、创建组合、成员蓝图、状态维护。
   - 保存记录：默认层、目录、执行跟进、成员跟进、来源复核、成员底稿。
   - 来源复核重新打开自动组/自定义组合后的路径。
   - 单台续费处理弹窗/面板作为辅助路径，不应抢占组合决策主线。
3. 保持现有业务能力和数据合同：
   - 不修改后端 API、数据库 schema、请求 URL、写入 payload contract。
   - 不新增前端依赖，不引入新的状态库或 e2e 框架。
   - 不新增嵌套 modal。
   - 不删除已有可完成业务动作；只调整入口层级、默认展示密度、文案和布局。
4. 用户可见文案本轮统一中文：
   - 页面、弹窗、eyebrow、导航、按钮、空状态、错误状态、辅助文案中不保留英文噪音。
   - API 机器值、内部 ID、调试字段不进入默认层和普通任务面板。
   - 代码类型、变量名、测试描述可继续使用英文；本轮不建立 i18n 字典。
5. “无需决策”状态必须不打扰：
   - 没有待决策组、漂移、阻塞、回读缺证据、资料缺口或局部错误时，默认页显示安静的稳定/空状态。
   - 稳定状态不渲染夸张的警示色、大面积主 CTA、重复统计卡或引导用户“处理”的文案。
   - 用户仍可主动切换视图、查看历史记录、场景模板或单台辅助队列。
6. 视觉审查必须先于实施结论：
   - 使用当前 `main` 基线上的真实运行态重新审查，不把前序 release 或测试通过当作 goal 完成证据。
   - 浏览器审查必须覆盖桌面 `1440x1000` 和移动 `390x900`。
   - 审查输出应包含截图、每个关键状态的文本/控件/表单/表格/行数指标、横向溢出检查和人工视觉结论。
   - 规划阶段使用可视化 companion 展示审计结论、布局方向或密度对比，供用户确认后再进入实施。

## Acceptance Criteria

- [ ] 页面默认首屏能在桌面 `1440x1000` 和移动 `390x900` 下明确呈现当前判断、主工作项或安静稳定状态，不需要用户跨三屏寻找重点。
- [ ] 页面默认态不出现英文 eyebrow 或中英文混杂的用户可见标签，例如 `PORTFOLIO`、`RENEWAL`、`CLOSED LOOP`、`EVIDENCE`、`WORKBENCH`、`SCENARIO`、`DECISION MEMORY`、`SINGLE VPS QUEUE`。
- [ ] 页面默认态不恢复教学式、答辩 PPT 式解释内容；记录、场景、续费事实和单台队列默认作为低权重入口或用户触发区。
- [ ] 辅助入口在桌面为一行紧凑工具条，在移动端为 2x2 小入口；每个入口只显示中文短标题、数量/状态和打开动作，不展示英文 eyebrow、长说明或默认表格。
- [ ] 当当前视图没有需要决策的问题时，页面显示低干扰的稳定/空状态；不出现制造紧张感的主警示、不必要的处理 CTA 或重复统计噪音。
- [ ] 自动组默认弹窗是短封面：对象、短判断、最多 1-2 个关键状态/风险信号、一个主动作和详情入口；不出现成员列表、成员姓名、保存表单、执行编排、来源回读、证据矩阵或底稿。
- [ ] 自动组详情目录只显示短入口和数量/短状态；不出现成员名、内部 ID、字段解释、完整说明句或英文报告标题。
- [ ] 自动组 `members`、`save`、`raw` 等面板彼此隔离；普通任务面板不混入宽表、底稿、保存表单或其它任务的解释。
- [ ] 自定义组合默认层、目录、编辑、成员、添加成员、保存记录、底稿路径均符合单任务短面板规则；隐藏的高级字段不会以用户看不见的旧 draft 提交。
- [ ] 场景模板默认层和普通任务面板中文、短面板化；状态维护的长确认文案只在用户触发确认后出现。
- [ ] 保存记录默认层、目录、执行跟进、成员跟进、来源复核、成员底稿路径互相隔离；执行面板只做状态推进和可执行成员动作，来源面板只做来源复核入口。
- [ ] 来源复核重新打开源自动组或自定义组合后，目标弹窗仍符合对应默认层、目录和二级面板规则。
- [ ] 现有 URL deep link 继续工作：`view`、`renew_within_days`、`group_id`、`manual_group_id`、`record_id`、`template_id`、legacy `view=single_queue`。
- [ ] 现有写路径继续工作：创建自定义组合、更新自定义组合、添加/移除成员、保存组合决策记录、从模板创建组合、更新模板状态、更新记录状态、成员跟进、单台续费决策。
- [ ] 针对默认层、目录层和典型二级面板有测试覆盖文本密度、控件数量、表单数量、表格数量、预览行数量和禁止跨任务内容；测试不只反向搜索旧 marker。
- [ ] `cd web && npm run lint` 通过。
- [ ] `cd web && npm run test -- --run AssetDecisionsPage.test.tsx` 通过。
- [ ] `cd web && npm run test -- --run` 通过。
- [ ] `cd web && npm run build` 通过。
- [ ] `git diff --check` 通过。
- [ ] 浏览器截图审查覆盖页面默认态、稳定/空状态、自动组、自定义组合、场景模板、保存记录、来源复核、移动端关键路径；无 document/body 横向溢出。
