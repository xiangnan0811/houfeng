# 资产组合决策中枢证据质量增强

## Goal

在 Phase 1 已完成的资产组合决策读模型与工作台基础上，补齐一层可解释的“证据质量与决策压力”派生模型，让用户能快速判断一个组合是否已经具备决策条件、当前压力来自哪里、下一步应偏向保存决策还是补齐证据。

## Requirements

- 只使用现有资产组合决策读模型已聚合的事实：VPS、订阅、服务、域名、Target、监控关联、生命周期、续费窗口、现有 evidence chips。
- 不新增数据库表，不新增迁移，不新增会修改订阅、监控、Target 或执行取消/退役的动作。
- 为决策组和组内 VPS 成员输出结构化证据评估，至少包含：
  - 证据可信度或完整度评分。
  - 决策压力评分。
  - 执行准备度评分。
  - 质量等级或状态，用于区分“证据足够”“可用但需复核”“证据薄弱”“证据阻塞”。
  - 推荐偏向，用于表达 keep / observe / complete_evidence / retire / migrate 等下一步倾向。
  - 风险、支撑、缺口的简要计数或摘要。
- 证据源不可用时不能误判为缺订阅、缺监控等业务事实；应降低可信度并明确为“证据源不可用”类缺口。
- 已保存组合决策记录的 group/member evidence_snapshot 必须保存当时的证据评估，方便后续回看当时判断基础。
- 前端 `/asset-decisions` 需要在组合列表、组详情、决策记录详情中展示证据评估，视觉层级高于零散 evidence chips，但低于组合事实本身。
- 保留现有单台队列与 `PATCH /api/vps/{id}` 行为，不改变提交 payload。

## Acceptance Criteria

- [ ] 后端能为正常承载且证据完整的 VPS/组合派生较高可信度、较高准备度和保留/复核偏向。
- [ ] 后端能为缺订阅、缺监控、缺服务上下文或资料缺失的 VPS/组合派生较低可信度与补证据偏向。
- [ ] 后端能为取消联动、预算风险、异常监控、闲置付费等场景派生较高决策压力。
- [ ] 订阅证据源不可用时，评估反映证据源问题，但不输出“缺订阅”的业务误判。
- [ ] `RecordSnapshotFromGroup` 和 `RecordSnapshotFromMember` 包含 evidence assessment。
- [ ] `/asset-decisions` 组列表展示证据质量/压力/准备度，并可被测试断言。
- [ ] 组详情成员表展示每台 VPS 的证据评估、建议角色/动作和关键证据。
- [ ] 决策记录详情展示保存时的证据评估快照。
- [ ] 前端单台续费决策测试仍证明 `PATCH /api/vps/{id}` payload 与现有行为一致。
- [ ] Go 单元测试、前端测试、类型检查和视觉 sanity 覆盖主要路径。

## Notes

- 本任务不是 Phase 2/3 的完整智能决策系统；性能衰退、路由质量、IP 质量、超售判断、手工组和批量执行仍留在后续增量。
