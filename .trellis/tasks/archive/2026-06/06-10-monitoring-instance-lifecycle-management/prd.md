# 监控实例生命周期管理

## Goal

为 MonitoringInstance 补齐完整管理能力，让用户可以安全地区分“继续观测、暂停、退役、归档、恢复、永久清理”，并能处理之前因为“重复创建并接入 agent”造成的空监控实例。实现后，监控实例不再只有新增接入路径，已有实例升级、错误实例清理、关联 VPS/历史数据保护都应有明确入口和后端约束。

## Background

- 之前的 agent 升级流程只考虑新增接入，导致已接入 VPS 点击“接入 agent”后会创建新的 MonitoringInstance，新老实例共存，实际 agent 上报仍绑定旧实例。
- 新创建的错误实例通常没有观测数据，暂停或归档都不能表达“这是误创建对象，应删除”。
- 当前 MonitoringInstance 有 `lifecycle_status`、`monitoring_status`、绑定 token、心跳、主机样本、探测观测、IP 质量上报、VPS 链接、事件和通知等关联数据，但没有面向监控实例本身的生命周期管理和清理审查。
- 现有 `BuildSyncPlan` 已对 `已退役` 或 `暂停` 返回空计划，但同步批处理会在构建计划前写入心跳、主机样本、探测观测和 IP 质量报告，因此暂停/退役仍可能继续沉淀新数据。
- VPS 资产已经有归档审查和确认弹窗模式，可以复用其“先审查影响，再执行危险操作”的产品和工程模式。

## Requirements

### 状态语义

- `lifecycle_status` 继续表示接入/观测生命周期：`待接入`、`在用`、`观察中`、`不续费`、`已退役`。
- `monitoring_status` 继续表示运行控制：`启用`、`维护中`、`暂停`。
- 归档不是新的 `lifecycle_status`。新增独立归档字段，使实例可以退出默认工作集，同时保留历史和关联。
- 永久清理是独立危险操作，表示删除监控实例及其可删除关联数据；它不是暂停、退役或归档的别名。

### 用户能力

- 监控实例详情页提供统一管理入口，而不是把危险操作散落在列表、运行控制和接入流程中。
- 管理入口必须展示实例当前状态、是否归档、绑定状态、活跃 VPS 关联、数据/历史引用计数、警告、阻塞项和可执行操作。
- 用户可以直接退役实例。退役后实例应停止监控、撤销待执行 action，并让 agent 后续同步只得到空计划且不再写入新观测数据。
- 用户可以从退役状态恢复。恢复后默认进入“观察中 + 暂停”，要求用户显式恢复监控或重新接入，避免恢复即开始采集。
- 用户可以归档已退役且无活跃阻塞关系的实例。归档后实例退出默认列表，撤销接入/同步 token 和待执行 action，不允许继续接入、下发动作或写入新观测数据。
- 用户可以从归档恢复。恢复后实例回到“观察中 + 暂停”，需要用户显式处理后续监控/接入。
- 用户可以永久清理误创建的空实例。对于有真实观测、历史、通知、事件或生命周期动作引用的实例，必须通过审查提示风险，并要求先归档后再清理。
- 管理面板必须暴露活跃 VPS 关联，并提供跳转或复用现有解绑路径，避免清理/归档时用户不知道有哪些资产受影响。

### API 和后端约束

- `GET /api/monitoring-instances` 支持 `scope=active|archived|all`，默认 `active`。
- 新增管理审查接口：`GET /api/monitoring-instances/{id}/management-review`。
- 新增生命周期操作接口：
  - `POST /api/monitoring-instances/{id}/lifecycle/retire`
  - `POST /api/monitoring-instances/{id}/lifecycle/restore`
  - `POST /api/monitoring-instances/{id}/archive`
  - `POST /api/monitoring-instances/{id}/restore-from-archive`
  - `POST /api/monitoring-instances/{id}/permanent-cleanup`
- 危险操作输入必须包含明确原因；归档和永久清理还必须有名称确认，防止误操作。
- 后端必须在事务内锁定实例、重新计算审查结果，再执行归档或永久清理，避免前端审查结果过期。
- 永久清理必须先删除没有外键级联保护的引用，再删除 `monitoring_instances`，并依赖已有外键级联删除心跳、样本、观测、IP 质量子表和 VPS 链接。
- 归档实例必须阻断接入 token 签发、安装命令、绑定确认/拒绝/重置、runtime resume、动作下发和元数据编辑。
- 暂停、退役或归档实例的 agent 同步必须返回空计划，且不再持久化新心跳、主机样本、探测观测和 IP 质量报告。

### 前端体验

- 监控实例列表提供 `active / archived / all` 范围切换，默认只看 active。
- 监控实例批量操作只对 active 且未归档实例开放。
- 详情页新增“管理实例”入口，打开审查面板/弹窗后再执行退役、恢复、归档、恢复归档、永久清理。
- 危险操作使用现有 `ActionConfirmationModal` 风格，归档和永久清理必须输入实例显示名确认。
- 操作完成后刷新实例详情、审查数据、列表和相关 runtime/onboarding 状态。

## Acceptance Criteria

- [ ] 数据库迁移新增归档字段和必要约束，不改变既有 `lifecycle_status` 枚举语义。
- [ ] 默认监控实例列表不显示归档实例；`scope=archived` 只显示归档实例；`scope=all` 显示全部实例。
- [ ] 管理审查接口返回实例、活跃 VPS 关联、可执行操作、阻塞项、警告和所有清理相关计数。
- [ ] 退役操作将实例设置为 `已退役 + 暂停`，清除待执行 action，并撤销会导致继续接入/控制的 token。
- [ ] 从退役恢复后实例为 `观察中 + 暂停`，不会自动恢复采集。
- [ ] 归档操作仅在无阻塞项时成功；成功后设置归档字段、撤销 token、清除待执行 action，并退出默认工作集。
- [ ] 归档恢复后实例清除归档字段并进入 `观察中 + 暂停`。
- [ ] 空误创建实例可永久清理；有历史/观测/事件/通知/动作引用的实例必须先归档且经过名称确认才能永久清理。
- [ ] 永久清理删除非外键引用和实例本体，不留下孤儿记录；原有外键级联数据被数据库清除。
- [ ] 暂停、退役、归档实例的同步请求不再写入新心跳、主机样本、探测观测或 IP 质量报告，并返回空计划。
- [ ] 归档实例不能签发接入/安装命令，不能执行 runtime resume 或 action dispatch。
- [ ] 前端详情页有统一管理入口，显示关联、计数、警告、阻塞项和操作按钮。
- [ ] 前端列表范围切换、批量操作过滤、操作后刷新行为通过测试覆盖。
- [ ] 后端 store、handler/router/bootstrap、迁移、同步批处理有单元或集成测试覆盖。

## Out of Scope

- 不重做 agent 安装脚本或升级命令生成策略；本任务只保证实例管理和清理语义完整。
- 不引入多用户 RBAC、操作者审计身份或软删除回收站。
- 不修改 VPS 生命周期模型；只在审查中读取并展示相关 VPS 链接。
- 不迁移既有历史数据为新的生命周期状态；已有实例默认未归档。

## Process Constraints

- 本任务必须在非 `main` / `master` 分支完成。
- 实现、检查、Trellis 任务完成和归档都必须先完成；只有任务归档后，才允许 push 分支或创建 PR。
- 如果执行中发现方案遗漏或现有代码事实不支持当前设计，先回到计划 artifacts 修正，再继续实现。
