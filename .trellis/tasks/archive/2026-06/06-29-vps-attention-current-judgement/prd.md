# Integrate VPS attention states into current judgement

## Goal

VPS 详情页所有“需要用户处理 / 核对 / 跳转”的当前状态都归入顶部“当前判断”区域，避免中部页面继续出现独立的状态提醒条，让页面保持“详情页”而不是“中转页 + 提醒堆叠”。

## Requirements

- 顶部“当前判断”必须承载单台 VPS 当前最重要的状态判断和处理入口，包括但不限于：
  - 取消 / 退役 / 迁移联动处理。
  - 运行观测异常或健康状态需要核对。
  - 订阅读取失败、真实缺少当前订阅、临近续费或已取消自动续费。
  - 缺少运行观测。
  - IP 质量报告不可用。
- “运行观测需要核对”等同类状态不得再以中部独立横条展示。
- 多个关注状态同时存在时，顶部当前判断不能只显示其中一个动作；应按严重程度展示可理解的多状态列表，并提供对应操作入口。
- 稳定状态下顶部保持紧凑，不额外展示啰嗦解释文案；动作显示为“无”或等价的短状态。
- 中部“关联概览”“单机台账”“IP 质量概况”等页面内容保留当前主体结构，不重新设计外部订阅、监控或 IP 质量详情页。
- 所有相关操作继续使用现有 modal / 跳转规则：基础资料、订阅、agent、监控观测、服务、域名、资产历史等在本页通过 modal 管理；订阅列表、监控实例详情、IP 质量详情保持跳转。
- 不改后端 API contract，不新增真实数据字段，不用抽屉，不把新状态区域插入页面中部。

## Acceptance Criteria

- [ ] 当 MonitoringInstance 有活跃异常或健康状态非正常时，“运行观测需要核对”显示在顶部“当前判断”内，并提供“查看监控实例 / 监控观测”入口。
- [ ] 同一场景下页面中部不再渲染独立的“需要处理的状态”横条，也不出现 `vps-detail-context-action` 区域。
- [ ] 取消 / 退役相关状态仍只在顶部当前判断暴露“处理取消/退役”，稳定状态仍隐藏该危险入口。
- [ ] 订阅读取失败、缺订阅、缺运行观测等现有 context action 场景仍有可用入口，但入口归属到顶部当前判断。
- [ ] 多个关注状态可同时出现在顶部当前判断，不会被单个 `primaryAction` 覆盖。
- [ ] 现有关联概览标题点击、快速动作和 modal / route 行为不回退。
- [ ] 增加或调整回归测试覆盖上述行为。

## Notes

- 用户明确要求不要再把“取消/退役工作台”这类状态作为中部突兀区域；本任务将该原则推广到所有需要处理的当前状态。
- 用户对冗长提示文字高度敏感；新 UI 文案必须短，避免解释“为什么这里能点”。
- 当前代码已存在 `buildContextAction` 能识别大部分状态，但它被 `VPSContextActionPanel` 渲染在中部；顶部当前判断只特殊接了取消/退役，这是根因。
