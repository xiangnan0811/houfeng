# Simplify asset decision modals

## Goal

资产组合决策页的所有详情弹窗必须从“长文档/大表堆叠”改为“默认概览工作台”。用户打开自动组、自定义组、保存记录或场景模板时，首屏只能承载判断所需的最小信息：关键事实、当前判断、主要行动、少量成员/快照摘要。更多成员、原始表格、保存/编辑表单、执行跟进、来源复核和模板创建必须通过明确的二级入口进入，不能默认铺在同一滚动流里。

这次返工的核心不是只删除截图中出现的旧标题，而是修正上一轮遗漏的默认内容承载模型。截图里的“预算压力与弱承载”只是一个证据样本；验收必须覆盖所有资产决策详情弹窗类型。

## Requirements

- 全面审查 `/asset-decisions` 中所有详情弹窗：自动组详情、自定义组合详情、已保存组合决策记录详情、场景模板详情、以及从记录复核来源打开的组详情。
- 默认概览只能展示：
  - 紧凑事实摘要；
  - 当前判断/主结论；
  - 主要行动按钮；
  - 少量可扫描成员或快照摘要。
- 以下内容不得默认渲染在概览流中：
  - 原始宽表格；
  - 保存记录表单；
  - 自定义组合编辑表单；
  - 添加/编辑/移除成员表单；
  - 记录执行编排全量 lane；
  - 记录成员跟进全量表单；
  - 来源连续性大区块；
  - 模板创建表单；
  - 模板成员蓝图全量列表；
  - “原始明细会保留在下方”“如何理解矩阵”“继续查看原始明细”这类解释性兜底句。
- 二级内容必须通过清晰入口进入，例如“成员明细”“原始明细”“保存记录”“编辑组合”“执行跟进”“来源复核”“从模板创建”等；进入后保留原有能力，不丢功能。
- 自动组详情必须保留创建自定义组合、保存为决策记录、处理单台 VPS、查看 VPS/取消退役工作台能力，但默认不把处理面板和保存表单铺开。
- 自定义组合详情必须保留保存组合、保存为决策记录、另存为模板、编辑组合、添加/编辑/移除成员能力，但默认不铺开编辑表单和添加表单。
- 保存记录详情必须保留状态更新、成员跟进、执行编排、来源复核、成员表格能力，但默认只展示保存时判断和下一步入口。
- 场景模板详情必须保留归档/启用、从模板创建组合、成员蓝图查看能力，但默认不铺开创建表单和成员蓝图列表。
- 证据表达必须诚实：预算压力、弱承载、缺证据、退役/取消风险不能因为降噪而被隐藏成稳定状态。
- 桌面和移动端都不能出现 document/body 横向溢出；宽表格只能在其二级面板的内部滚动容器中横向滚动。
- 不改后端 API、数据库 schema 或新增依赖。

## Acceptance Criteria

- [ ] 自动组详情默认打开时不出现旧标题 `场景推进建议`、`证据矩阵 / 取舍对比`，也不出现 `asset-table` 宽表、保存记录表单、单台处理面板或“原始明细/继续查看原始明细”解释句。
- [ ] 自动组详情默认打开时仍能看到组名、成员数、成本、证据质量、当前判断、创建自定义组合、保存为决策记录、至少一条关键成员摘要和处理/VPS入口。
- [ ] 自动组详情点击二级入口后，成员明细、原始表格、保存记录表单和单台处理面板仍可使用，且写 API payload 不变。
- [ ] 自定义组合详情默认打开时不出现 `组合推进状态`、`自定义组合证据矩阵`，也不出现组合编辑表单、成员添加表单、成员全量编辑表单或原始表格。
- [ ] 自定义组合详情默认打开时仍能看到 readiness、目标/来源、主要动作入口、成员摘要和意图状态；点击二级入口后保存组合、保存记录、另存模板、添加/编辑/移除成员仍可用。
- [ ] 保存记录详情默认打开时不出现全量执行编排、来源连续性区块、成员跟进表单或原始成员表格；默认只展示保存时判断、证据快照摘要、状态/跟进/执行计数和进入二级面板的入口。
- [ ] 保存记录详情点击执行/成员/来源入口后，状态更新、成员跟进、执行 CTA、来源复核和成员表格仍可用，且不触发 VPS/订阅/监控/Target 写 API。
- [ ] 场景模板详情默认打开时不出现模板创建表单或成员蓝图全量列表；点击创建/成员/状态入口后原能力可用。
- [ ] 测试不再只断言旧标题缺失；必须反向断言默认概览不会渲染关键噪音元素，并正向断言二级入口可展开原能力。
- [ ] 浏览器验证覆盖 1440x1000 和 390x900：打开自动组、自定义组合、记录、模板详情，检查 document/body 无横向溢出，默认视图没有长表/长表单/旧解释区，关键行动可见。
- [ ] `git diff --check`、`cd web && npm run test -- --run AssetDecisionsPage.test.tsx`、`cd web && npm run lint`、`cd web && npm run test -- --run`、`cd web && npm run build` 通过。
