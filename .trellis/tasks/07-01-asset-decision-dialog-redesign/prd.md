# 重构资产组合决策组详情弹窗

## Goal

资产组合决策页的二级详情面板必须和已重构的默认页保持同等信息架构质量。打开任意决策组、场景组合或相关详情时，用户应能在首屏直接看出“现在要判断什么、首要结论是什么、下一步能做什么”，而不是被大量解释性文字、重复标签、横向矩阵和长滚动弹窗淹没。

## Requirements

- 全面审查 `/asset-decisions` 的详情弹窗和二级 surface，不只修截图中的“预算压力与弱承载”。
- 自动组详情弹窗必须从“解释型长文档”改为“决策型工作台”：首屏优先展示结论、关键事实、成员取舍和行动。
- 自定义组详情、已保存记录详情、场景模板详情若存在同类文字堆叠或结构噪音，也必须纳入审查并处理，不能只局部修一个入口。
- 去除或折叠低价值解释性文案，例如“为什么需要这个区块”“建议如何理解矩阵”这类不会直接帮助决策的文字。
- 保留必要事实证据：成员、订阅/成本、承载上下文、监控/Target、证据质量、建议动作、保存记录/创建自定义组合入口。
- 证据表达必须诚实：缺数据、弱承载、预算压力、退役/取消风险不能被过度概括成稳定或可闭环。
- 移动端和桌面端都不能出现页面级横向溢出；弹窗内部可滚动但首屏不能被冗余说明占满。
- 不引入新的后端/API/数据库/依赖变化，除非审查证明前端无法单独解决并另行说明。

## Acceptance Criteria

- [ ] 打开自动决策组详情时，首屏只保留一个清晰 header、一个紧凑事实摘要、一个主判断/行动区和成员取舍列表入口；不再默认展示“场景推进建议”“证据矩阵 / 取舍对比”等大段解释区块。
- [ ] 自动组详情中的每个成员以可扫描的决策行/卡呈现：名称、建议角色/动作、成本/订阅、承载/监控、风险/缺口、处理入口；重复性标签数量受控。
- [ ] 自动组详情仍能保存为决策记录、创建自定义组合，并保持原有 URL deep link 行为。
- [ ] 自定义组详情和记录详情完成同类审查；若保持现状，必须有证据说明它们没有同类问题，否则同步整改。
- [ ] 测试覆盖弹窗首屏信息架构：禁止旧大段标题默认出现，验证关键行动和成员事实仍存在。
- [ ] 运行前端 lint、相关 Vitest、全量前端测试和 build。
- [ ] 使用浏览器或标准 visual evidence helper 验证 `/asset-decisions` 桌面与移动视口：弹窗可读、无页面级横向溢出、关键行动可见。
